# 历史纵向基线数据源（Historical Baseline）v1.2

> 本文件定义节假日消费数据集的**历史纵向基线库**：来源、清单、与 SKILL 22 字段 schema 的对账（reconciliation）适配器、基于真实数据校验出的口径/取值漂移与质量规则，以及**调用时实时拉取机制**（v1.1 新增；v1.2 移除内置快照，纯实时拉取）。
> 用途：跨年数据整理（去年同期 / 本年上期 / 中长期趋势）的唯一可信历史源；也是「纵向延续与前瞻」章节与可选第六交付物（跨年纵向专题）的取数底座。

### 1.1 调用时实时拉取机制（默认开启）

**结论：可行，且已实测验证**（2026-08-20：匿名 `git clone --depth 1` 约 9 秒，`git pull` 增量正常）。机制设计如下：

| 项 | 规则 |
| --- | --- |
| 触发时机 | 阶段一结束前（纵向数据归集前）执行一次「基线拉取」；用户显式要求"更新基线/刷新历史数据"时立即执行 |
| 镜像目录 | 默认 `{报告输出目录}/.baseline-cache/`（输出目录下，可写、可随报告归档）；可用参数 `baseline_dir=` 覆盖 |
| 拉取动作 | 首次：`git clone --depth 1 <上游URL> {镜像目录}`；后续：`git -C {镜像目录} pull --depth 1`（增量，秒级） |
| 成功 | 本次纵向分析读取实时镜像；报告页脚注明 `历史基线版本: live@<commit短号> (YYYY-MM-DD HH:mm)` |
| 离线降级 | clone/pull 失败（无网/仓库不可达/限流）→ 本次纵向模块标注「**本期为首期基线，暂无去年同期/上期预测可比**」（沿用首期降级逻辑），报告页脚注明 `历史基线: 未获取（离线/仓库不可达）`；**不编造历史数字** |
| 空镜像保护 | 镜像目录存在但为空/损坏 → 删除重建 clone；clone 再次失败按离线降级处理 |
| 并发安全 | 与协同空间约定一致：同一时刻仅一个客户端活跃；拉取动作加 `.lock` 文件互斥，避免多客户端同时 pull 冲突 |

**边界条件（务必遵守）**：
1. **技能安装目录只读**：基线镜像**严禁**写入 `~/.workbuddy/skills/` 或技能包内部，只写输出目录下的 `.baseline-cache/`（或用户指定可写目录），保证技能包本身不被污染。
2. **离线环境**：无网络时实时拉取必然失败 → 纵向模块降级为首期基线标注，流程不中断；不得回退到任何过期数据冒充最新。
3. **不覆盖不删除**：实时镜像只增不删；每次 pull 前不执行 `git clean/reset`，保留仓库原始文件与历史（`--depth 1` 已控制体积）。
4. **仓库漂移**：若上游仓库结构变更（新增年份/节假日目录、字段改版），以仓库最新结构为准，差异在报告中如实声明。

## 二、schema 对账：历史 17 字段 → SKILL 22 字段

历史 CSV 由专家团 P0 落地，**17 字段**（含口径元数据），是 SKILL 22 字段 schema 的**严格子集**（17 ⊂ 22）。接入时只需**补 5 个派生字段**，无需删改。

### 2.1 历史 17 字段
`主题 | 数据点 | 数值 | 单位 | 来源机构 | 报告/资料名 | 发布时间 | 可信度等级 | URL | 备注 | 假期天数 | 口径类型 | 基期 | 统计窗口 | 数值类型 | 采集日期 | 缺口标记`

### 2.2 SKILL 22 字段中历史缺失的 5 字段（接入时派生默认值）
| 缺失字段 | 派生规则（历史接入默认值） |
| --- | --- |
| `单位粒度` | 由 `单位` 推：亿人次→人次，亿元→亿元，%→百分比，元→元，家/场次/列/个→对应；无法推断标 `待核` |
| `统计起止日` | 由 `假期天数`+节假日查 `holiday-config.md` 放假区间推算；调休/合并年标 `待核` 并在备注记原始窗口 |
| `口径版本` | 由 `统计窗口`+`假期天数` 推：`8天口径`/`9天口径`/`7天口径`/`7-8月合计`；无则 `合并口径` |
| `指标口径类型` | 由 `主题`+`数据点` 查**指标口径字典**归族（出游/收入/交通/住宿/平台…）；无法归标 `待核` |
| `数据性质` | 默认 `实际`（实测）；若 `数值类型=增长率` 且无基数→仍 `实际`（系机构已披露）；明显派生值标 `推算` |

## 三、纵向 join 的关键：数据点规范化（跨年对齐铁律）

> **实测结论（最重要）**：对 20 个 CSV 扫描，按 `(节假日, 数据点, 口径类型)` 能在 ≥3 年同时出现的元组**仅 1 个**（十一·北京接待游客·官方总量）。根因：历史 `数据点` 字段**内嵌年份/节假日名**（如 `2023春节国内旅游出游人次` vs `2024春节国内旅游出游人次`），导致同名无法跨年 join。

### 3.1 数据点 canon 键（canonical key）
纵向对比前，必须对所有 `数据点` 做**去年份/去节假日名**规范化，生成稳定 join 键：

```
canon(数据点) = 去掉前缀年份(20\d\d)、去掉中缀节假日名(春节/五一/端午/暑假/十一/中秋)、去掉「今年/去年/同期」等相对词
例： "2023春节国内旅游出游人次" → canon = "国内旅游出游人次"
     "2024五一国内出游人次"      → canon = "国内出游人次"
```

### 3.2 纵向比对元组（stable join key）
跨年可比性判定键 = **`(节假日, canon(数据点), 口径类型, 地域scope)`**，四元一致且覆盖 ≥2 年才允许做同比/环比叙事；否则标记为**单年/不可比**，不得编造趋势线。

- `地域scope`：全国 / 省级 / 城市 / 平台。历史 CSV 中 `总体` 主题下混入省级行（如 2025 暑假·云南），须按 `来源机构` 还原 scope，禁止把省级当全国比。
- 假期天数不同年份的，先按 `caliber-dictionary.md` 第一节**折算为日均或可比天数**再比（拦截未折算绝对量比较）。

### 3.3 去年同期 / 本年上期取数流程
1. 由参数解析出 `[年份][节假日]`。
2. 在基线库定位**上一年同节假日** CSV（去年同期）与**本年已发生的上一个节假日** CSV（本年上期）。
3. 两库均做 canon 规范化 + 枚举归一 + 口径对齐。
4. 按 3.2 元组匹配，输出可比数据点对；不匹配的列入「不可比/单年」附录。
5. 预测复盘：若上一年该数据点 `数据性质=预计` 或 `缺口标记=预判待回填`，调取本年实测回填，做偏差归因（口径效应/外生变量/方法偏差）。

## 四、基于真实数据校验出的质量规则（新增 R13–R15）

| 风险 | 规则 | 实证（历史数据） |
| --- | --- | --- |
| **R13 数据点年内耦合** | `数据点` 禁止内嵌年份/节假日名；纵向分析前必须 canon 规范化，否则跨年 join 失效 | 716 行中仅 1 元组跨 ≥3 年可直接 join |
| **R14 非数值误标水平值** | `数值` 为非数值（列表/定性句/「是」「超X成」「X月」）时，`数值类型` 必须=`定性` 或 `复合`（含「/」的列表），**禁标 `水平值`** | 59 行数值非数值却标 `水平值`（如 `三亚/厦门`、`近700`、`是`、`超四成`、`3-12月`） |
| **R15 口径/主题未归一** | 接入历史数据时，`复合值`→`复合`、`政策与宏观`→`消费宏观`、`热门新消费`→`新消费`、`目的地`/`跨境`/`出入境`→`景区目的地`，否则纵向聚合分裂 | `复合值`37 行、主题漂移 45 行（`政策与宏观`12+`热门新消费`42+`目的地`44 等未并入 9 类） |

### 4.1 字典补录（权威化历史实证类型）
- `口径类型取值表` 新增 **`官方重点监测`**（文旅部重点监测景区/样本企业，21 行实证，层级 L1），与 `官方总量` 区分：总量为全域，重点监测为监测样本。**字典 v2.0 已收录，无需再改**。
- `数值类型` 明示：`复合值` 为历史别名，**统一写作 `复合`**（37 行实证）。
- `主题` 历史取值按 **2.3 节归一表**映射到字典 9 类：`政策与宏观`→`消费宏观`、`热门新消费`/`新消费`→`新消费`、`目的地`/`跨境`/`出入境`→`景区目的地`、`消费`/`支付`/`放假安排`/`群众文化`/`电影`→`消费宏观`。**字典 9 类为权威，历史别名一律归并，不再扩类**（修复 R5 漂移：政策宏观/政策与宏观、新消费/热门新消费并存问题）。

> 主题字典以 `caliber-dictionary.md` 第四节现行 9 类定义为权威；本表为历史接入归一映射，二者冲突时以字典为权威、本表为准入映射。

## 五、使用约束

- 历史基线用于**纵向对比与趋势**，不替代当年采集；当年报告仍以阶段一~四新采数据为主，基线仅作对照轴。
- 2026 各 CSV 多为**进行中/前瞻**（如 2026 十一仅 6 行且全为放假安排/政策宏观），属预测台账输入，不得当作实测消费值。
- 量级校验：历史 `单位` 与当年 `单位` 必须一致（亿人次 vs 人次）方可比；不一致先换算。
- **纯实时基线（v1.2）**：SKILL 调用时实时拉取至 `.baseline-cache/`（唯一路径）；**不再内置快照**。在线必有最新基线（页脚 `live@<commit>`）；离线/拉取失败时纵向模块降级为首期基线标注（页脚 `未获取`），**不得用任何过期数据冒充最新**。
- **L2 豁免（v3.5）**：17→22 适配只约束 **L1 结构化行**。历史 CSV 中入不了 22 字段的榜单/区间/定性/政策素材（其实证文本已在历史 `数值`/`备注` 列），**不参与 17→22 适配**，直接复制进 `现象素材库`（L2）原样保留并附 URL，不因口径门槛被丢弃（详见 `references/data-architecture.md`）。
