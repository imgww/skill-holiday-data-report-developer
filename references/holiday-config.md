# 节假日配置参考（Holiday Configuration Reference）v2.0

> v2.0（v4.1 改造，Y 议题 · P0-2）起，本文件从「逐节日同构文本」升级为**三张结构化配置**：**属性卡 / 口径地图 / 锚点日历**。差异由「结构字段」表达，可被采集器/分析器机器读取，不再藏在散文「特殊注意」里。
> 参数化原理：**统一内核（analysis-methodology）+ 每节日配置（本文件）+ 少数结构特例**。换节日 = 换配置，不换内核。
>
> **重要口径提示（消除 6→5 缺口）**：本流程外壳为「六类节假日」，但**并非每年都产六套独立报告**。当中秋与国庆临近或重叠时，当年实际只有五套独立数据集。禁止静默缺位——须在 `overview.md` 与真实性说明明确声明「本年中秋与国庆合并统计」，数据集备注列标注 `含中秋口径`（见 `caliber-dictionary.md` 第八节与本文 §4 `merge_mode`）。

## §2 三张配置说明（schema 定义）

> 克制原则（防止参数化过度）：配置只写**可观测锚点**，不写分析结论（结论由数据决定）；每节日配置 ≤2 页，超过则回退到分析内核；分化止步于**配置差异**，不升级为方法论差异；跨节比较被约束而非取消（配置显示数据本体不同时，自动降级为「节奏观察」而非「斜率比较」）。

### 配置一 · 属性卡（驱动分析模型参数化，≤2 页/节日）

```yaml
属性卡 [节日]:
  制度锚点:        # 哪些部门在定义这个时间窗口
  社会锚点:        # 属性→品类因果链（与 analysis-methodology §4 对接）
  事件锚点:        # 人生事件（写作框架需登记，Y-d）
  可比边界:        # 哪些能比、哪些不能比（Y-b）
  词表三变体:      # 制度名 / 学制名 / 口语名
  制度来源部门:     # Y-c 新增字段（多部门，非单一文旅）
  merge_mode:      # 仅十一/中秋：independent | merged | adjacent
```

### 配置二 · 口径地图（每节日数据源清单）

```yaml
口径地图 [节日]:
  官方总量:        # 有/无（如春节有文旅部通稿；暑假无）
  官方专题:        # 有/无（如暑假有 CTA 专题 + OTA 联合样本）
  官方连续:        # 有/无（如全部节日都有统计局 CPI 分项价格序列）
  市场总量:        # 有/无（如暑假有咨询「3.2 万亿」测算，标叙事化）
  平台交易:        # 各平台可用性（携程/同程/飞猪/美团…）
  数据口vs宣传口:  # 分层（如文旅部：数据中心不发暑期 / 宣传口发定性综述）
```

### 配置三 · 锚点日历（时间线上的可观测锚点）

```yaml
锚点日历 [节日]:
  前置锚点:        # 假期开始前已发生的可观测事件
  期内锚点:        # 假期内
  后置锚点:        # 假期结束后
  # 每锚点 = {日期 | 可观测指标 | 制度来源部门 | 权威源}
```

### 1. 暑假（样板 · 完整对照，第 15–18 轮官方语料实证）

**属性卡 · 暑假**
```yaml

可比边界:    无文旅部全国通稿；只有 CTA+OTA 样本、CPI 价格序列；禁「十一 vs 暑假」总量斜率比较
词表三变体:  暑期（制度名，官方全用）/ 暑假（口语/学制名，SKILL 现用）
制度来源部门: 交通部、教育部、应急管理部（非文旅部单一部门）
```

**口径地图 · 暑假**
```yaml
官方总量:    无（文旅部数据中心不发暑期全国总量）
官方专题:    有（CTA 专题 + OTA 联合样本，2024–2025 断层）
```

**锚点日历 · 暑假**

## §4 结构特例（显式声明，替代散文）

三个节日的结构差异从散文升级为显式声明：

| 特例 | 显式声明内容 |
| --- | --- |
| **暑期** | 无假日通稿 + 多部门制度覆盖（交通/教育/应急）+ 只能做结构与价格分析 |
| **十一中秋** | `merge_mode: independent（独立 3 天）/ merged（合并 8 天+）/ adjacent（相邻未合并）`，用字段不用散文 |
| **春节** | 春运 + 跨农历年耦合（统计区间跨年，天数 7/8/8/9 漂移） |

**十一中秋合并判定规则（merge_mode 落地）**：每年执行采集前，先确认国务院办公厅当年放假安排，按 `merge_mode` 三态确定中秋处理方式，并在 `overview.md` 显式声明：

| merge_mode | 当年安排 | 处理方式 | 命名与数据集标注 |
| --- | --- | --- | --- |
| `independent` | 中秋为独立 3 天假期 | 独立采集一套报告 | 命名 `[年度]中秋假期`；「口径版本」=`3天口径` |
| `merged` | 中秋与国庆合并为超长假期（8 天+） | 并入相邻国庆，产一套合并报告 | 命名 `[年度]十一假期（含中秋）`；备注标 `含中秋口径` |
| `adjacent` | 中秋紧邻国庆但未合并 | 两套独立报告，各自标注区间 | 中秋数据极少时 overview 注明「数据量有限」 |

**硬约束**：禁止静默缺位；合并年份的「六类节假日」口径改为「当年实际 N 套」，口径字典第八节同步适用。

## §6 纵向延续与预测规则（保留）

### 规则一：放假安排已知 → 开启前瞻窗口
- 每年采集前先确认国务院办公厅放假安排（尤其春节/五一/十一/中秋的天数与 merge_mode）。
- 放假安排公布后即开启「下一节假日前瞻」窗口：写入 `数据性质=预计` + `缺口标记=预判待回填` 预测行，生成 `预测ID`（格式 `[年度][节假日]-F0X`）。
- 前瞻预测**不得当实测**：报告用预测卡（中心值+区间+置信度+口径效应提示），数值类型标 `水平值`、口径类型标 `测算`、可信度强制 D。

### 规则二：预测台账回填时点
- 下一报告期阶段二读取上一期 `缺口标记=预判待回填` 行 → 填实测值 → 算偏差% → 归因（口径效应/外生变量/方法偏差）→ 改 `缺口标记=已回填-偏差X%` 或 `已回填-吻合`。
- 典型回填时点：2026 十一预判于 **2026-10-08**（假期结束次日）回填。
- 偏差 > ±10% 必须标「失准」并写三类归因，不得掩盖（详见 `templates.md` 第 6 节偏差卡）。

### 规则三：去年同期 / 本年上期回顾
- **去年同期（YoY）**：取去年同节假日核心指标，**必须先 per-day 折算**（天数归一，口径字典第一节）再比较；判读「增量来自天数/口径」还是「真实增长」。
- **本年上期**：本节假日 vs 本年已发生节假日，判读年内消费节奏与增速收敛斜率。
- 首期生成时标注「本期为首期基线，暂无去年同期/上期预测可比」，不编造对比。

### 规则四：中长期趋势预判
- 未来 3–12 月及更久的结构性判断，分级标注 `已验证 / 待核验 / 存疑`，并给**拐点判据**（可观测指标，提前 1–2 假期预警），无美化、无选择性引用。
