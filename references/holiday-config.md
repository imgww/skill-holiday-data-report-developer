# 节假日配置参考（Holiday Configuration Reference）

本文件列出六类中国法定节假日/假期的参数化配置，供阶段一数据采集时确定检索方向与全源覆盖。v1.2 起数据源优先级由"ABC 三级"升级为"全源 A–J 分组矩阵"，并新增全源采集门禁与纵向/预测规则（详见下方专章）。

> **重要口径提示（消除 6→5 缺口）**：本流程外壳为"六类节假日"，但**并非每年都产六套独立报告**。当中秋与国庆临近或重叠（如 2023、部分年份出现"中秋+国庆"超长假期）时，当年实际只有五套独立数据集。禁止静默缺位——须在 `overview.md` 与真实性说明中明确声明"本年中秋与国庆合并统计"，并在数据集备注列标注 `含中秋口径`，使"六类节假日"外壳与实测报告数不矛盾（见 `caliber-dictionary.md` 第八节）。

## 全源数据采集矩阵（A–J 分组）

> v1.2 新增。阶段一检索不再只盯"政府/媒体/平台"三级，而应按下列 **A–J 十组全源** 并行铺开，保证口径互补、缺口可标注。每组给出典型源与适用场景；各节假日的具体侧重见下方逐节配置与"特殊注意"。

| 组 | 名称 | 典型数据源 | 在消费报告中的角色 |
| --- | --- | --- | --- |
| **A** | 政务公开 | 文化和旅游部、商务部、交通运输部、国铁集团、民航局、国家发改委、央行/外汇局、海关总署、国家统计局、移民管理局 | 官方总量、跨区域含自驾、营业性不含自驾口径的**主干来源**（L1–L2） |
| **B** | 行业机构 | 中国旅游研究院、中国饭店协会、中国旅行社协会、STR、中国烹饪协会、中国连锁经营协会、艾瑞/易观/QuestMobile | 行业协会计、景气指数、结构性口径（L2–L3） |
| **C** | 平台渠道 | 携程、同程、飞猪、途牛、美团、滴滴、高德、抖音生活服务、京东/天猫 | 平台自披露 GMV/订单/热度，须标"平台自身口径非全市场"（L3） |
| **D** | 企业财报 | 上市旅企（中青旅、复星旅文、首旅/锦江/华住）、航司年报、景区上市公司 | 供给侧经营验证，交叉印证行业景气（L2–L3） |
| **E** | 支付清算 | 银联商务、网联、支付宝、微信支付（消费频次/金额指数） | 高频消费脉冲、线下小额消费景气（L2–L3） |
| **F** | 舆情社媒 | 微博、小红书、抖音、知乎热榜（声量/情绪/种草） | 新消费热点发现、客群情绪、内容平台种草信号（L3–L4） |
| **G** | 地图 POI | 高德/百度地图 POI 热度、拥堵、迁徙热力 | 实时客流强度、目的地热度、迁徙节律（L2–L3） |
| **H** | 招投标专利招聘 | 政府采购网、招投标平台、专利库、招聘景气 | 供给侧投资/产能/用工前瞻（L3–L4） |
| **I** | 气象口岸 | 中央气象台、移民管理局（出入境）、口岸客流 | 外生变量（天气/口岸）对出行的扰动与免签兑现核验（L1–L2） |
| **J** | 投诉舆情 | 黑猫投诉、12315、文旅部投诉平台 | 服务体验风险、消费维权缺口（L3–L4） |

**全源覆盖提示**：A 组（官方主干）为每报告期必采；C 组（平台自披露）与 B 组（行业机构）为结构互补必采；E/F 至少覆盖一组以补高频/情绪维度；G/I/J 按节假日特性选采（如春节重 I 气象口岸、十一重 J 投诉舆情）。具体门禁见"全源采集门禁"专章。

## 跨节假日通用检索策略

1. **全源矩阵**（所有节假日通用）：按上表 A–J 十组并行铺开，A 主干必采，C/B 结构互补必采，E/F 至少一组，G/I/J 按特性选采。
2. **政府数据源**（A 组）：文化和旅游部假期总结公告、商务部消费数据、国铁集团客运数据、民航局/航班管家数据、交通运输部公路/水路数据、移民管理局口岸数据。
3. **平台数据源**（C 组）：携程、同程、飞猪、途牛、美团、途家等平台假期报告（须标"平台自身口径非全市场"）。
4. **探索性主题**（所有节假日通用）：检索词为 `[年度] [节假日] 新消费热点 / [年度] [节假日] 消费新业态 / [年度] [节假日] 新兴消费`，禁止预置具体业态。
5. **旧闻剔除规则**：所有节假日通用，凡非目标年度/节假日口径的数据一律不入库。

## 全源采集门禁（v1.2 新增）

阶段一/阶段二收尾时，由 `audit_caliber.py`（专家团 P0 已落地）与人工复核双重把关；未达标须显式声明缺口，禁止静默缺位。

### 门禁一：最小覆盖门禁
每报告期数据集须至少覆盖以下分组，否则在 `overview.md` 与真实性说明声明缺口：
- **必采**：A（政务公开主干）+ C（平台渠道）+ B（行业机构）
- **至少一组**：E（支付清算）或 F（舆情社媒）
- **选采但建议**：G（地图 POI）、I（气象口岸）、J（投诉舆情）按节假日特性覆盖

### 门禁二：采集深度行数门禁（R10）
数据集有效记录行数（剔除 `[旧闻-剔除]` 与空值行）须达到下表下限，低于下限须复核并标记 `缺口标记=空/全国总量缺项`：

| 节假日 | 最低行数 |
| --- | --- |
| 春节 / 十一 | ≥ 35 |
| 五一 / 端午 / 独立中秋 | ≥ 25 |
| 暑假 | ≥ 30 |

> 行数门禁仅作"采集充分性"下限校验，不替代口径健康分（L1–L4 可信度等级占比、per-day 折算完整性等）。行数达标但口径单一（如全为 C 级平台自披露）仍判为缺口。

## 纵向延续与预测规则（v1.2 新增）

延续性是 v3.3 框架的第二部分（报告"纵向延续与前瞻"模块）与预测台账闭环的机制底座。配置层约定如下：

### 规则一：放假安排已知 → 开启前瞻窗口
- 每年执行阶段一**前**，先确认国务院办公厅当年放假安排（尤其春节/五一/十一/中秋的天数与是否合并）。
- 一旦放假安排公布，即对本报告期开启"下一节假日前瞻"窗口：在数据集写入 `数据性质=预计` + `缺口标记=预判待回填` 的预测行，并生成 `预测ID`（格式 `报告期-序号`，如 `2026十一-F01`）。
- 前瞻预测**不得当实测**：报告中以"预测卡"呈现（中心值+区间+置信度+口径效应提示），数值类型标 `水平值`、口径类型标 `测算`、可信度等级强制 `D`。

### 规则二：预测台账回填时点
- 下一报告期阶段二读取上一期 `缺口标记=预判待回填` 行 → 填入实测值 → 计算偏差% → 归因（口径效应/外生变量/方法偏差）→ 改 `缺口标记=已回填-偏差X%` 或 `已回填-吻合`，判语标 `吻合`/`失准`。
- 典型回填时点：2026 十一预判于 **2026-10-08**（假期结束次日）回填；春节预判于次年假期结束次日回填。
- 偏差 > ±10% 必须标「失准」并写三类归因，不得掩盖（详见 `templates.md` 第 6 节偏差卡骨架）。

### 规则三：去年同期 / 本年上期回顾
- **去年同期（YoY）**：从 SSOT 多年份 CSV 取本节假日去年同节假日核心指标，**必须先 per-day 折算**（假期天数归一，口径字典第一节）后再比较；增量须判读"来自天数/口径"还是"真实增长"。
- **本年上期**：本节假日 vs 本年已发生节假日（如十一 vs 五一/端午/暑假），判读年内消费节奏与增速收敛斜率。
- 首期生成（无可比历史）时，2.2/2.4 标注「本期为首期基线，暂无去年同期/上期预测可比」，不编造对比。

### 规则四：中长期趋势预判
- 对未来 3–12 月及更久的结构性判断，须分级标注 `已验证 / 待核验 / 存疑`，并给出**拐点判据**（可观测指标，提前 1–2 假期预警），无美化、无选择性引用。

## 中秋与国庆合并/独立判定规则（消除 6→5 缺口）

每年执行阶段一前，**先确认国务院办公厅当年放假安排**，按以下规则确定中秋的处理方式，并在 `overview.md` 显式声明：

| 当年安排 | 处理方式 | 命名与数据集标注 |
| --- | --- | --- |
| 中秋为**独立 3 天**假期 | 独立采集一套报告 | 命名 `[年度]中秋假期`；「口径版本」=`3天口径`、`统计起止日`=中秋实际区间 |
| 中秋与国庆**合并**为超长假期（如 8 天+） | 并入相邻国庆，产一套合并报告 | 命名 `[年度]十一假期（含中秋）` 或 `[年度]中秋国庆假期`；数据集「备注」列标注 `含中秋口径` |
| 中秋紧邻国庆但**未合并**（如间隔数日） | 独立采集中秋；国庆独立采集 | 两套独立报告，各自标注区间；若中秋数据极少可在 overview 注明"中秋独立报告数据量有限" |

**硬约束**：
- 禁止静默缺位：若某年实际无独立中秋报告，必须在 `overview.md` 与真实性说明声明"本年中秋与国庆合并统计"，不得让"六类节假日"外壳与实际五套报告矛盾。
- 合并年份的"六类节假日"口径改为"当年实际 N 套"，口径字典第八节同步适用。
