# 数据架构：双层数据模型 + 分年分节持久化（Data Architecture）v1.0

> 本文件定义 SKILL 的数据资产模型。背景：早期版本（10 字段、78 行）信息丰度高但口径弱；v3.3+ 统一 22 字段口径后，**该节日时点特有的现象与价值信息（榜单/区间/定性句/政策事件）被口径治理"筛掉"**（实证：2026 暑假早版 78 行 vs 最新版 46 行，同名数据点仅 1 个，丢失的 77 条几乎全是现象层信息）。
> 解法：**数据双轨分层**——统计性质强的进 L1 结构化层（保延续性），URL/HTML 等原始资源进 L2 非结构化现象层（保丰度）；并**按 年份/节假日 分目录持久化沉淀**，实现跨期资产积累。

---

## 一、双层数据模型（Two-Layer Data Model）

### L1 结构化层（Statistical Layer）——「延续性」的脊柱
| 项 | 说明 |
| --- | --- |
| 载体 | 数据集 CSV，**强制 22 字段**（`templates.md` 第 2 节） |
| 收录标准 | **统计性质强、可直接入趋势线**：官方总量/口径明确的指标，`数值类型 ∈ {水平值, 增长率}`（可入线）或 `复合`（可拆解） |
| 治理 | 口径字典 v2.1 全量约束：canon 数据点、口径类型/基期/数值类型/数据性质/缺口标记、跨年可比四元键、预测台账 |
| 用途 | 去年同期/本年上期/跨年趋势、同比环比、预测复盘——一切**纵向可比**叙事 |
| 反模式 | L1 禁止混入榜单/定性句/区间（R14）；禁编造（反模式 #11） |

### L2 非结构化现象层（Evidence & Phenomenon Layer）——「时点丰度」的血肉
| 项 | 说明 |
| --- | --- |
| 载体 | `现象素材库`（JSON 结构化元数据 + Markdown 可读版 + 原文 HTML 快照） |
| 收录标准 | **凡采集到但不足以/不适合入 L1 的素材全部保留**：榜单（TOP10 清单）、区间值（130%/60% 区间）、定性句（"显著增长""翻倍"）、政策事件（免签/消费券/放假安排）、平台自披露热点、图片/图表/长文摘录 |
| 治理 | 轻量标签化：`现象标签`/`主题归属`/`素材类型`/`来源URL`/`采集日期`/`与L1指标键`（可选关联），**不做 22 字段口径强制**（口径字典仅作主题映射参考） |
| 用途 | 本期「热门新消费」「现象观察」「政策与宏观」「目的地热点」章节素材；跨期**现象字典**（同一现象连续多年出现→升级为 L1 指标）；真实性说明的证据链 |
| 反模式 | L2 禁止冒充统计值写进趋势线；进入正文须标注"现象级/定性素材,非统计口径" |

### 双轨关系（L1 ↔ L2）
- **L2 是 L1 的候选池与证据库**：某现象连续 ≥2 期出现且可量化 → 提炼为 L1 指标（如"清凉圈酒店预订同比"从现象升级为年度跟踪指标）。
- **L1 是 L2 的锚点**：L2 条目若有对应 L1 指标，记 `与L1指标键`（canon 数据点），报告呈现时双向可跳。
- 报告四件套：L1 撑起"纵向延续与前瞻"（严谨），L2 撑起"本期现象与热门新消费"（丰度），两者分栏呈现、不混同。

## 二、分年分节持久化（Per-Year-Per-Holiday Persistence）

### 2.1 输出目录约定（每个报告期独立目录）
```
data/
└── {年份}/                      # 2023 / 2024 / 2025 / 2026 ...
    └── {节假日}/                 # 春节 / 五一 / 端午 / 暑假 / 十一 / 中秋(独立时)
        ├── 数据集.csv            # L1 结构化层（22 字段,必出）
        ├── 现象素材库.json       # L2 现象层·机器可读（元数据,必出）
        ├── 现象素材库.md         # L2 现象层·可读版（报告/真性说明引用）
        ├── 素材快照/             # L2 原文 HTML/PDF/图片快照（尽力而为,命名=来源机构_标题摘要）
        ├── 采集日志.csv          # 阶段一检索记录
        ├── 消费数据报告.html     # 四件套之二
        ├── 数据真实性说明.html   # 四件套之三
        └── index.html            # 四件套之四（门户）
```

### 2.2 目录即资产库（与历史基线同构）
- 上述 `data/{年份}/{节假日}/` 结构与历史基线上游仓库 `g_ww/holiday_data_reports` 的 `{年份}/{节假日}/` 结构**完全同构**（v3.7 起技能包不内置快照，历史基线随调用实时拉取至 `.baseline-cache/`，见 `references/historical-data-source.md`）。
- 每期完成后，将本期 `数据集.csv` + `现象素材库.json` 提交/同步至历史基线上游（atomgit 仓库 `g_ww/holiday_data_reports`），实现**持续沉淀**：下期纵向分析直接读取，无需重新采集历史。
- 跨期聚合（跨年纵向专题/现象字典）＝扫描所有 `data/{年份}/{节假日}/数据集.csv` 与 `现象素材库.json` 后按 canon/标签归并。

### 2.3 覆盖矩阵（沉淀追踪）
每期在 `overview.md` 登记：`[年份][节假日] 已沉淀：L1=xx 行 / L2=xx 条 / 快照=xx 个`；未产出的期次（如缺中秋单列）在覆盖矩阵标注"合并入十一"或"未采"，不静默缺失。

## 三、L2 现象素材库 Schema（JSON）

```json
{
  "schema": "phenomena-library-v1",
  "year": 2026,
  "holiday": "暑假",
  "region": "全国",
  "collected_at": "2026-08-20",
  "items": [
    {
      "id": "2026-SH-P001",
      "现象标签": ["避暑游", "目的地热度"],
      "主题归属": "景区目的地",
      "现象描述": "\"20度清凉圈\"城市酒店预订量同比超50%",
      "数值": "超50%",
      "单位": "",
      "数值类型": "定性(区间/约)",
      "素材类型": "榜单/热点",
      "来源机构": "去哪儿旅行",
      "来源URL": "https://...",
      "采集日期": "2026-08-14",
      "与L1指标键": "清凉圈城市酒店预订同比",
      "HTML快照": "素材快照/去哪儿_清凉圈.html",
      "备注": "平台自披露口径,非全市场;连续第2年出现,建议升L1跟踪"
    }
  ]
}
```

### 字段说明（必填：现象描述/来源URL/采集日期；其余尽力）
| 字段 | 说明 |
| --- | --- |
| `现象标签` | 自由标签（避暑游/研学/反向旅游/县域奔县/入境游/平台榜单/政策事件/价格现象/结构变化…），跨期归并用 |
| `主题归属` | 按口径字典 9 类映射（仅作归类，不做强制校验） |
| `数值/单位/数值类型` | 原样保留（榜单清单存 `数值=清单文本,数值类型=定性`），**不做口径折算** |
| `素材类型` | 数据点/榜单清单/定性陈述/区间值/政策事件/图文摘录/图表 |
| `与L1指标键` | 有对应 L1 指标时填 canon 数据点；无则空 |
| `HTML快照` | 本地快照相对路径；无法保存时填"未存"并在备注记原因 |

### Markdown 可读版（现象素材库.md）
```markdown
# [年份][节假日] 现象素材库（L2 非结构化层）
> 说明：本库收录该节假日时点特有的现象/榜单/定性/政策素材，供报告"本期现象与热门新消费"章节与真实性说明引用。素材不进入 L1 统计口径，引用时须标"现象级素材"。

## 一、本期现象速览（按现象标签归并）
| 现象标签 | 代表素材 | 来源 | 采集日期 |
| --- | --- | --- | --- |

## 二、素材明细（按素材类型分组）
### 榜单清单
- **[现象标签] 现象描述** — 来源机构（URL）· 采集日期 · [与L1指标键]
### 区间值 / 定性句
...
### 政策事件
...
```

## 四、双轨在五阶段中的落地

| 阶段 | L1 结构化层 | L2 非结构化现象层 |
| --- | --- | --- |
| 阶段一·采集 | 检索 22 字段口径所需指标；记录采集日志 | **同源双录**：每轮检索除结构化数据点外，把榜单/区间/定性/政策/热点 URL 一并记入采集日志 `内容摘要`，并下载原文快照（尽力） |
| 阶段二·整理 | 22 字段口径治理（现有全流程） | 将采集日志中非 L1 素材整理进 `现象素材库.json/.md`：贴标签、归主题、记 URL/快照/关联键；**不被 22 字段门槛拒绝** |
| 阶段三·输出 | 真实性说明（L1 逐条溯源） | 真实性说明增「现象素材清单」节：列 L2 条目来源 URL，声明"现象级素材,非统计口径" |
| 阶段四·报告 | 纵向延续与前瞻（严谨叙事） | 本期现象/热门新消费/目的地热点/政策速览章节（丰度叙事），引用 L2 并标素材属性 |
| 阶段五·交付 | 四件套 + 数据集 | 目录按 `data/{年份}/{节假日}/` 落盘；`现象素材库.json/.md` 入交付清单；overview 登记沉淀矩阵 |

## 五、质量红线（双轨专用）

1. **L1/L2 不混同**：L2 素材进入报告正文必须标"现象级/定性素材"，禁止伪装成统计口径数字入趋势线（违反即判反模式 #11/#14）。
2. **L2 不因口径被丢弃**：凡采集到但入不了 L1 的素材，必须落 L2 库（宁多勿缺），唯一例外是无 URL 佐证的纯臆测——直接删除。
3. **沉淀必登记**：每期 overview 登记 L1/L2/快照数量；缺失期次在覆盖矩阵显式标注，不静默。
4. **现象→指标升级通道**：同一现象标签连续 ≥2 期出现且可量化 → 下期纳入 L1 固定采集项（写入 `holiday-config.md` 检索词/指标清单），形成"现象→指标"正向循环。
5. **快照版权与隐私**：原文快照仅本地留存、不入公开报告；引用时给可点击 URL，不整篇转载。
