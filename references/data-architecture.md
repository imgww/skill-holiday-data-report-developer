# 数据架构：统一采集数据集（Unified Fetch Dataset）v1.2.0

> 本文件定义 SKILL 的数据资产模型。背景：早期版本（10 字段、78 行）信息丰度高但口径弱；v1.3.3+ 统一 22 字段口径后，**该节日时点特有的现象与价值信息（榜单/区间/定性句/政策事件）被口径治理"筛掉"**（实证：2026 暑期早版 78 行 vs 最新版 46 行，同名数据点仅 1 个，丢失的 77 条几乎全是现象层信息）。
> 解法：**数据分层但不分文件**——以「统一采集数据集」单一 JSON 承载全部采集成果，L1（统计层）与 L2（现象层）通过每条记录的 `layer` 字段区分，**不再拆成两套独立格式**。并**按 年份/节假日 分目录持久化沉淀**，实现跨期资产积累。

---

## 一、统一采集数据集（单一 JSON · L1/L2 合并）

### 1.1 总体结构
采集产物为**一个** `holiday-data-fetch.json`，顶层三键：

```json
{
  "schema": "holiday-data-fetch-v1",
  "meta": {
    "year": 2026,
    "holiday": "暑期",
    "region": "全国",
    "created_at": "2026-08-29",
    "updated_at": "2026-09-02",
    "rounds": ["2026-08-28-R1", "2026-08-31-R2", "R3", "R4", "2026-09-02-R5"],
    "caliber_version": "holiday-data-report-caliber-v2.1",
    "holiday_config_version": "holiday-keywords-v1.0",
    "merge_notes": ["2026-08-28-R1: 新增 55 条, 去重 0 条, 冲突 0 条, 观测关联 0 对", "..."],
    "counts": { "L1": 240, "L2": 56, "snapshots": 293, "history_imported": 0 },
    "holiday_seq": "SH",
    "_all_ids": [
      { "id": "2026-SH-L1-001", "layer": "L1" },
      { "id": "2026-SH-L2-001", "layer": "L2" }
    ]
  },
  "items": [ /* L1 与 L2 记录合并于此，由 layer 字段区分 */
    { "layer": "L1", "id": "2026-SH-L1-001", "主题": "总体", "数据点": "7月国内旅游人次", "数值": "12.3", "单位": "亿人次", "...": "..." },
    { "layer": "L2", "id": "2026-SH-L2-001", "主题归属": "景区目的地", "现象描述": "…", "现象标签": ["避暑游"], "...": "..." }
  ]
}
```

- **L1/L2 不分开**：所有采集记录进入同一个 `items` 数组，`layer` ∈ `{L1, L2}` 为唯一判别字段（参照 `holiday-data-fetch.json`）。
- `meta.counts` 同时给出 L1/L2 条数，便于登记与校验；`_all_ids` 预登记全部 id 与 layer，防止 id 冲突。
- `schema` 固定为 `holiday-data-fetch-v1`；`meta.caliber_version` / `holiday_config_version` 记录口径与检索词版本，保证可溯源。

### 1.2 L1 统计层（layer=L1）——「延续性」的脊柱
| 项 | 说明 |
| --- | --- |
| 判别 | `items[].layer == "L1"` |
| 收录标准 | **统计性质强、可直接入趋势线**：官方总量/口径明确的指标，`数值类型 ∈ {水平值, 增长率}`（可入线）或 `复合`（可拆解） |
| 字段 | 强制 22 字段口径（`caliber-dictionary.md`）：`主题 / 数据点 / 数值 / 单位 / 单位粒度 / 数值类型 / 数据性质 / 口径类型 / 指标口径类型 / 口径版本 / 基期 / 假期天数 / 统计窗口 / 统计起止日 / 发布时间 / 可信度等级 / 地域粒度 / 缺口标记 / 备注 / 推算依据 / 内容摘录`（外加 `id / layer / round / 观测批次 / 采集日期 / 采集时间 / 来源机构 / 报告·资料名 / 来源URL / URL / snapshot / 快照复用 / keywords / 与L1指标键` 等治理字段） |
| 治理 | 口径字典全量约束：canon 数据点、口径类型/基期/数值类型/数据性质/缺口标记、跨年可比四元键、预测台账 |
| 用途 | 去年同期/本年上期/跨年趋势、同比环比、预测复盘——一切**纵向可比**叙事 |
| 反模式 | L1 禁止混入榜单/定性句/区间（R14）；禁编造（反模式 #11） |

### 1.3 L2 现象层（layer=L2）——「时点丰度」的血肉
| 项 | 说明 |
| --- | --- |
| 判别 | `items[].layer == "L2"` |
| 收录标准 | **凡采集到但不足以/不适合入 L1 的素材全部保留**：榜单（TOP10 清单）、区间值（130%/60% 区间）、定性句（"显著增长""翻倍"）、政策事件（免签/消费券/放假安排）、平台自披露热点、图片/图表/长文摘录 |
| 字段 | 轻量标签化：`主题归属 / 现象描述 / 现象标签 / 素材类型 / 数值 / 单位 / 数值类型 / 来源机构 / 来源URL / 采集日期 / 与L1指标键（可选关联） / HTML快照 / 备注`；**不做 22 字段口径强制**（口径字典仅作主题映射参考） |
| 治理 | 仅轻量标签化，`数据性质` 可标 `现象级`；`数值类型` 标 `定性(区间/约)`；不进入 L1 统计口径 |
| 用途 | 本期「热门新消费」「现象观察」「政策与宏观」「目的地热点」章节素材；跨期**现象字典**（同一现象连续多年出现→升级为 L1 指标）；真实性说明的证据链 |
| 反模式 | L2 禁止冒充统计值写进趋势线；进入正文须标注"现象级/定性素材,非统计口径" |

### 1.4 分层但不分文件（L1 ↔ L2 关系）
- **L2 是 L1 的候选池与证据库**：某现象连续 ≥2 期出现且可量化 → 提炼为 L1 指标（如"清凉圈酒店预订同比"从现象升级为年度跟踪指标）。
- **L1 是 L2 的锚点**：L2 条目若有对应 L1 指标，记 `与L1指标键`（canon 数据点），报告呈现时双向可跳。
- 报告呈现：L1 撑起"纵向延续与前瞻"（严谨），L2 撑起"本期现象与热门新消费"（丰度），两者在报告中分栏呈现、不混同——但**源头同属一个 `items` 数组**。

## 二、分年分节持久化（Per-Year-Per-Holiday Persistence）

### 2.1 输出目录约定（数据与报告分置两棵子树）

交付根目录固定为 **`holiday-data-reports/`**：

```
holiday-data-reports/
├── data_set/
│   └── {年份}_{节假日}/              # 2026_暑期 / 2025_暑期 / 2026_春节 ...
│       ├── holiday-data-fetch.json   # ★ 统一采集数据集（L1+L2 合并,必出,唯一事实来源 SSOT）
│       ├── 采集日志.csv              # 阶段一检索记录
│       └── snapshots/                # 原文 HTML/PDF/图片快照（按需单点补拉）
└── data_report/
    └── {年份}_{节假日}/
        ├── 消费数据报告.html          # 经济学人/FT 风格
        ├── 数据真实性说明.html        # 逐条溯源与质量声明
        └── index.html                # 门户入口
```

> **单一事实来源（SSOT）**：`holiday-data-fetch.json` 是全部数字的唯一来源。
> L1/L2 由 `layer` 字段区分；按层派生的可读视图需要时现算，**不落盘为独立交付物、不进交付清单**。

### 2.2 目录即资产库（与历史基线同构）
- 上述 `data_set/{年份}_{节假日}/` 结构与历史基线上游仓库 `g_ww/holiday_data` 的 `{年份}_{节假日}/` 结构**完全同构**（历史基线随调用实时稀疏检出至 `holiday-data-reports/data_set/`，见 `references/historical-data-source.md`）。
- 每期完成后，将本期 `holiday-data-fetch.json` 同步至历史基线上游（atomgit 仓库 `g_ww/holiday_data`），实现**持续沉淀**：下期纵向分析直接读取，无需重新采集历史。
- 跨期聚合（跨年纵向专题/现象字典）＝扫描所有 `holiday-data-reports/data_set/{年份}_{节假日}/holiday-data-fetch.json` 后按 `layer` + canon/标签归并。

### 2.3 覆盖矩阵（沉淀追踪）
每期在 `overview.md` 登记：`[年份][节假日] 已沉淀：L1=xx 行 / L2=xx 条 / 快照=xx 个`；未产出的期次（如缺中秋单列）在覆盖矩阵标注"合并入十一"或"未采"，不静默缺失。

## 三、统一数据集 Schema（JSON，{schema,meta,items}）

```json
{
  "schema": "holiday-data-fetch-v1",
  "year": 2026, "holiday": "暑期", "region": "全国",
  "items": [
    {
      "layer": "L1",
      "id": "2026-SH-L1-001",
      "主题": "总体",
      "数据点": "7月国内旅游人次",
      "数值": "12.3", "单位": "亿人次", "单位粒度": "人次",
      "统计起止日": "2026-07-01 至 2026-08-31", "统计窗口": "7-8月合计",
      "口径版本": "暑期口径", "指标口径类型": "接待游客人次", "口径类型": "官方总量",
      "数据性质": "实际", "基期": "同比", "假期天数": 62, "数值类型": "水平值",
      "采集日期": "2026-08-28", "缺口标记": "空",
      "来源机构": "文化和旅游部", "报告/资料名": "2026年7月国内旅游数据", "发布时间": "2026",
      "可信度等级": "A", "URL": "http://...", "备注": "同比增长18.7%",
      "内容摘录": "文旅部：2026年7月国内旅游人次12.3亿(+18.7%)",
      "地域粒度": "全国", "keywords": "2026 暑期 7月出游", "推算依据": "",
      "采集时间": "2026-08-29 14:00", "观测批次": "R1", "数据来源": "本轮采集",
      "round": "2026-08-28-R1", "snapshot": "snapshots/文化和旅游部_7月国内旅游人次.html", "id": "2026-SH-L1-001"
    },
    {
      "layer": "L2",
      "id": "2026-SH-L2-001",
      "主题归属": "景区目的地",
      "现象描述": "\"20度清凉圈\"城市酒店预订量同比超50%",
      "现象标签": ["避暑游", "目的地热度"],
      "数值": "超50%", "单位": "", "数值类型": "定性(区间/约)",
      "素材类型": "榜单/热点", "来源机构": "去哪儿旅行", "来源URL": "https://...",
      "采集日期": "2026-08-14", "与L1指标键": "清凉圈城市酒店预订同比",
      "HTML快照": "素材快照/去哪儿_清凉圈.html",
      "备注": "平台自披露口径,非全市场;连续第2年出现,建议升L1跟踪"
    }
  ]
}
```

### 字段说明（按 layer 区分必填）
**L1 必填**：`主题 / 数据点 / 数值 / 单位 / 数值类型 / 数据性质 / 口径类型 / 来源机构 / 可信度等级 / 采集日期`；其余（基期/统计窗口/缺口标记/备注/推算依据/快照等）尽力。
**L2 必填**：`现象描述 / 来源URL / 采集日期`；其余（现象标签/主题归属/素材类型/与L1指标键/HTML快照）尽力。
**两层的公共治理字段**：`id`（含 layer 段，如 `2026-SH-L1-001` / `2026-SH-L2-001`）、`layer`、`round`、`观测批次`、`采集时间`、`快照复用`。

## 四、统一格式在五阶段中的落地

| 阶段 | 统一采集数据集（L1+L2 合并 items） |
| --- | --- |
| 阶段一·采集 | 检索 22 字段口径所需指标 + **同源双录**：每轮检索除结构化数据点（layer=L1）外，把榜单/区间/定性/政策/热点 URL（layer=L2）一并记入采集日志 `内容摘要`，并下载原文快照（尽力） |
| 阶段二·整理 | 22 字段口径治理（L1 记录）；非 L1 素材整理为 L2 记录（贴标签、归主题、记 URL/快照/关联键）；**全部写入同一 `items` 数组，标 `layer`**，不被 22 字段门槛拒绝 |
| 阶段三·输出 | 真实性说明：L1 逐条溯源 + 「现象素材清单」节（L2 条目来源 URL，声明"现象级素材,非统计口径"），两节同源同一 JSON |
| 阶段四·报告 | 纵向延续与前瞻（L1 严谨叙事）+ 本期现象/热门新消费/目的地热点/政策速览（L2 丰度叙事），引用时标素材属性 |
| 阶段五·交付 | `holiday-data-fetch.json` + `采集日志.csv` + `snapshots/` 入 `data_set/`；三份 HTML 入 `data_report/`；**派生视图（CSV / 素材库等）不再产出、也不进交付清单**（按需从 SSOT 按 `layer` 现算）；交付说明登记 L1/L2/快照数量 |

## 五、质量红线（统一格式专用）

1. **L1/L2 同库不同叙事**：两者合并于同一 `items`，但报告/说明中 L2 素材进入正文必须标"现象级/定性素材"，禁止伪装成统计口径数字入趋势线（违反即判反模式 #11/#14）。
2. **L2 不因口径被丢弃**：凡采集到但入不了 L1 的素材，必须作为 `layer=L2` 记录落入统一数据集（宁多勿缺），唯一例外是无 URL 佐证的纯臆测——直接删除。
3. **派生视图不独立采集、也不单独交付**：任何按 `layer` 派生的可读视图仅由 `holiday-data-fetch.json` 现算，不得另行采集或手工维护，避免与 SSOT 漂移；且**不作为独立交付物落盘**。
4. **沉淀必登记**：每期 overview 登记 L1/L2/快照数量；缺失期次在覆盖矩阵显式标注，不静默。
5. **现象→指标升级通道**：同一现象标签连续 ≥2 期出现且可量化 → 下期纳入 L1 固定采集项（写入 `holiday-config.md` 检索词/指标清单），形成"现象→指标"正向循环。
6. **快照版权与隐私**：原文快照仅本地留存、不入公开报告；引用时给可点击 URL，不整篇转载。
