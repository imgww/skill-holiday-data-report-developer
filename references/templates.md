# 模板与字段规范（Templates & Schemas）

本文件提供四个阶段产出的结构化模板：采集日志（阶段一）、数据集（阶段二）、真实性说明（阶段三）、首页（阶段五）。执行时按模板产出,保证跨年度/跨节假日可复用、可校验。

## 1. 数据采集日志（阶段一产出）

每轮检索记录一行。字段与示例：

| 检索关键词 | 检索时间 | 标题 | 来源机构 | 报告/资料名 | 发布时间 | URL | 内容摘要 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| [年度][节假日]旅游人次 | [生成日期] | 文旅部：[节假日]出游X亿人次 | 中新网 | 文旅部假期数据发布 | [年度] | https://... | 出游X亿人次,+XX%,收入X亿 |

**记录规则**
- 每条记录对应一条"检索词 x 来源"组合;同一来源多条数据可合并一行（摘要中列出）。
- URL 必须为可点击完整链接,禁止缩写。
- 旧闻（非目标年度/节假日口径）单独标记 `[旧闻-剔除]` 并注明真实年份,不入数据集。

## 2. 数据集（阶段二产出 · 统一数据集的 L1 视图,CSV）

> **统一采集格式（v1.4.1）**：本期全部采集成果存于单一 `holiday-data-fetch.json`（`schema`/`meta`/`items`，每条带 `layer` 字段）。本节的「数据集 CSV」即 `items[layer=L1]` 的**派生视图**，字段顺序与下表一致；SSOT 仍是 JSON，CSV 仅便于报告 CSV 预览/下载与人工核查，不得独立采集。
> **v1.3.3 起强制 22 字段 schema**（合并 v1.3.2 的 16 字段与专家团 P0 的 17 字段口径元数据,去冗余后统一为 22 字段）。字段定义与取值见 `caliber-dictionary.md` 第〇节字段字典。

字段（顺序固定,不得删改列名）：
`主题 | 数据点 | 数值 | 单位 | 单位粒度 | 统计起止日 | 统计窗口 | 口径版本 | 指标口径类型 | 口径类型 | 数据性质 | 基期 | 假期天数 | 数值类型 | 采集日期 | 缺口标记 | 来源机构 | 报告/资料名 | 发布时间 | 可信度等级 | URL | 备注`

**等级标准**
- **A 级**：政府公告/官方统计/权威通讯社通稿（如文旅部、国铁集团、商务部、新华社、央视）
- **B 级**：权威媒体转引机构数据（如新浪财经、光明网、澎湃转引 STR/航班管家）
- **C 级**：企业自我披露/券商研报/行业机构报告（如携程数据报告、融创官方信息），C 级平台数据须标"该平台自身口径,非全市场"
- **D 级**：弱溯源/无法直接核实/推算（标注"弱溯源"或 `数据性质=推算`/`口径类型=测算`,附最接近佐证）；**推算/预计类强制 D 级,禁入 B 级**

**备注列常见标记**
- `测算`：AI 或第三方推算值,与实测数据分栏
- `弱溯源`：找不到直接出处,仅有相近口径
- `双口径`：存在多个统计口径,并列说明
- `转述性概括`：媒体转述,非原机构原文
- `平台自身口径`：C 级平台数据,非全市场代表
- `含中秋口径`：当年中秋与国庆合并统计时的标注
- `预测ID=...`：前瞻预测行的回标识,供下一期回填核验（口径字典第六节）

## 3. 数据真实性说明（阶段三产出,HTML 结构）

```
报头（Data Provenance / 数据真实性说明）
  |-- 引言
  |   |-- 数据采集与核实方法
  |   `-- 数据局限三项声明（时点口径差异 / 转述性概括 / 推算标注）
  |-- 可信度分级标准（A/B/C/D 定义 + 四色徽章图例）
  |-- 台账差异与修正声明（逐条列出与原稿/不同口径的差异与更正）
  |-- 逐条溯源表（按报告栏目分组）
  |   `-- 行格式：数据点 | 来源机构/报告/资料名 | 发布时间 | 等级徽章 | 可点击 URL
  |-- 测算与图表声明
  |-- 预测复盘与回填声明（若有上期预测：逐条列预测值→实测值→偏差%→归因；诚实标注吻合/失准）
  |-- 全量来源机构清单
  `-- 页脚
```

**溯源表行示例（HTML）**

```html
<tr>
  <td>[节假日]出游人次 XX.X 亿,+XX%</td>
  <td>文化和旅游部 / 假期数据发布（中新网转引）</td>
  <td>[年度]</td>
  <td><span class="badge a">A 级</span></td>
  <td><a href="https://..." target="_blank" rel="noopener">原文链接</a></td>
</tr>
```

**预测复盘声明示例（HTML）**

```html
<div class="forecast-review">
  <h4>上一周期预测复盘（忠实诚恳）</h4>
  <table class="data">
    <tr><th>预测事项</th><th>上期预测</th><th>实测值</th><th>偏差</th><th>归因</th><th>判语</th></tr>
    <tr><td>[上节假日]出游人次</td><td class="num">8.0 亿</td><td class="num">8.03 亿</td><td class="up">+0.4%</td><td>日均强度爬坡+免签兑现;中秋拆分口径效应已扣除</td><td>吻合(中置信)</td></tr>
  </table>
  <p class="note">若实测与预测偏离&gt;±10%,须明确写"失准",并区分口径效应/外生变量/方法偏差三类归因,不得掩盖。</p>
</div>
```

**修正声明写法**：`原稿口径 -> 更正后口径 -> 更正依据（来源+URL）`

**无公开 URL 的处理**：券商研报付费资料等如实标注"无公开 URL",并给出替代验证路径。

## 5. 预测台账（阶段二纵向归集产出,CSV/Markdown）

> 预测台账是「延续性」的机制底座：本期预测 → 下期回填核验 → 反哺预测方法论。与数据集同源,可单列 `预测台账.csv` 或用数据集 `数据性质=预计` + `缺口标记=预判待回填` 行表达。

字段：`预测ID | 所属报告期 | 预测事项 | 中心值 | 区间 | 置信度 | 口径效应提示 | 回填时点 | 实测值 | 偏差% | 归因 | 判语`

示例：

```csv
预测ID,所属报告期,预测事项,中心值,区间,置信度,口径效应提示,回填时点,实测值,偏差%,归因,判语
2026十一-F01,2026十一,国内出游人次,8.0亿,7.8-8.3亿,中,少1天+中秋不合并(口径效应非疲软),2026-10-08,8.03亿,+0.4%,日均强度爬坡+免签兑现,吻合
2026十一-F02,2026十一,国内游客总花费,7350亿,7100-7700亿,中,同上口径效应,2026-10-08,待回填,_,_,待回填
```

**回填规则**：下一报告期阶段二读取 `缺口标记=预判待回填` 行 → 填实测值 → 算偏差% → 归因（口径效应/外生变量/方法偏差）→ 改 `缺口标记=已回填-偏差X%` 或 `已回填-吻合`。偏差 > ±10% 必须标「失准」并写三类归因,不得掩盖。

## 6. 报告「纵向延续与前瞻」模块（阶段四新增,紧接导语）

> 这是 v1.3.3 报告框架的第二部分（位置前移,凸显数据延续性）。结构如下,逐节从数据集与预测台账取数。

```
第二部分 · 纵向延续与前瞻（CONTINUITY & OUTLOOK）
  |-- 2.1 口径裁决（先定规矩：天数/合并/人均/交通/平台口径,沿用口径字典）
  |-- 2.2 去年同期回顾（YoY）
  |   |-- 本节假日 vs 去年同节假日核心指标表（必须 per-day 折算后比较）
  |   `-- 增量主要来自"天数/口径"还是"真实增长"的判读
  |-- 2.3 本年上期回顾（同年内节奏）
  |   |-- 本节假日 vs 本年已发生节假日（如十一 vs 五一/端午/暑期）
  |   `-- 年内消费节奏、增速收敛斜率判读
  |-- 2.4 上一周期预测复盘（忠实诚恳）
  |   |-- 读取上期预测台账,逐条：预测值→实测值→偏差%→归因→判语
  |   `-- 收敛或失准的诚实陈述（不美化、不选择性引用）
  |-- 2.5 下一节假日前瞻（预测）
  |   |-- 预测卡：中心值+区间+置信度+口径效应提示（不得当实测）
  |   `-- 放假安排/免签/促消费政策等已知前置变量
  |-- 2.6 中长期趋势预判
  |   |-- 未来 3-12 月及更久的结构性判断（已验证/待核验/存疑 分级）
  |   `-- 拐点判据（可观测指标,提前 1-2 假期预警）+ 客群代际四象限（可选）
  `-- 数据风险与置信度声明（摘要,详细见真实性说明）
```

**首期降级**：若无可比历史（首次生成）,2.2/2.4 标注「本期为首期基线,暂无去年同期/上期预测可比」,不编造对比。

**历史基线取数**：2.2 去年同期、2.3 本年上期、2.6 中长期趋势的跨年数据,优先取自阶段一第 4c 步实时拉取的 `holiday-data-reports/data_set/`（2023–2026 × 5 节假日 = 20 CSV / 716 行,上游 `https://atomgit.com/g_ww/holiday_data`;**技能包不内置快照**）。接入按 `references/historical-data-source.md`：17→22 字段适配 + **数据点 canon 规范化** + 枚举归一。**跨年可比四元键** `(节假日, canon(数据点), 口径类型, 地域scope)` 一致且 ≥2 年才可比；历史库实测仅 1 元组跨 ≥3 年可直接 join,不 canon 规范化将无法跨年对比（实证：`数据点` 内嵌年份,如 `2023春节国内旅游出游人次`）。

## 8. L2 现象素材库（阶段二产出 · 统一数据集的 L2 分区,JSON + Markdown）

> 背景：22 字段口径治理会"筛掉"该节日时点特有的榜单/区间/定性/政策素材（实证：2026 暑期早版 78 行 vs 22 字段版 46 行,丢失的 77 条几乎全是现象层）。**统一格式（v1.4.1）下,L2 不再单独成文件**:这些素材作为 `layer=L2` 的记录写入同一个 `holiday-data-fetch.json` 的 `items` 数组。`现象素材库.json/.md` 仅是由 `items[layer=L2]` **派生的视图**,供报告"本期现象/热门新消费"章节与真实性说明引用。**L2 不做 22 字段口径强制**,仅轻量标签化。完整模型见 `references/data-architecture.md`。

### 8.1 L2 记录在统一数据集中的形态（items 元素,layer=L2）
```json
{
  "schema": "holiday-data-fetch-v1",
  "meta": { "year": 2026, "holiday": "暑期", "region": "全国", "counts": { "L1": 240, "L2": 56 } },
  "items": [
    {
      "layer": "L2",
      "id": "2026-SH-L2-001",
      "主题归属": "景区目的地",
      "现象描述": "\"20度清凉圈\"城市酒店预订量同比超50%",
      "现象标签": ["避暑游", "目的地热度"],
      "数值": "超50%",
      "单位": "",
      "数值类型": "定性(区间/约)",
      "素材类型": "榜单/热点",
      "来源机构": "去哪儿旅行",
      "来源URL": "https://...",
      "采集日期": "2026-08-14",
      "与L1指标键": "清凉圈城市酒店预订同比",
      "HTML快照": "素材快照/去哪儿_清凉圈.html",
      "备注": "平台自披露口径,非全市场;连续第2年出现,建议升L1跟踪"
    }
  ]
}
```

### 8.2 Markdown 可读版模板
```markdown
# [年份][节假日] 现象素材库（L2 非结构化层）
> 说明：本库收录该节假日时点特有的现象/榜单/定性/政策素材,供报告"本期现象与热门新消费"章节与真实性说明引用。素材不进入 L1 统计口径,引用时须标"现象级/定性素材,非统计口径"。

## 一、本期现象速览（按现象标签归并）
| 现象标签 | 代表素材 | 来源 | 采集日期 |
| --- | --- | --- | --- |

## 二、素材明细（按素材类型分组）
### 榜单清单
- **[现象标签] 现象描述** — 来源机构（URL）· 采集日期 · [与L1指标键]
### 区间值 / 定性句
- ...
### 政策事件
- ...
```

### 8.3 素材类型枚举
`数据点` / `榜单清单`（TOP10 等）/ `定性陈述` / `区间值` / `政策事件` / `图文摘录` / `图表`。

### 8.4 与 L1 的接口
- 有对应 L1 指标 → `与L1指标键` 填 canon 数据点（报告呈现可双向跳）。
- 同一现象标签连续 ≥2 期出现且可量化 → 备注"建议升 L1 跟踪",下期写入 `holiday-config.md` 检索词/指标清单（现象→指标升级通道）。
