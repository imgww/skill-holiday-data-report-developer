# 口径字典（Caliber Dictionary）v2.1

> 本文件是数据集与报告的**强制口径标准**，用于消除跨域共病「口径混用 / 未折算 / 推算未标 / 纵向不可比 / 预测无台账」。
> 凡数据集任意字段、报告任意数字，口径归属若落入本字典，必须按定义标注；不得随意替换、合并或默认。
> 本字典与 `templates.md` 的 **22 字段数据集 schema** 配套使用：每条数据的口径元数据列，必须能在本字典找到对应条目。
> v2.0 在 v1.0（口径规则）基础上，新增**统一主题字典 / 统一指标口径字典 / 口径类型取值表 / 基期规范 / 数值类型规范 / 预测台账规范**，并把字段标准从 16 字段升级为 22 字段（合并专家团 P0 已落地的 17 字段口径元数据）。

**等级标准**：A 政府公告/官方统计/权威通讯社通稿 ｜ B 权威媒体转引机构数据 ｜ C 企业自披露/券商研报/行业机构 ｜ D 弱溯源/无法直接核实/推算。
**强制 D 规则**：`数据性质=推算` 或 `口径类型∈{测算,弱溯源}` 或 `数值类型≠水平值` 的数据点，可信度**强制 D 级、禁入 B 级**，且与实测分栏、不得混同（消除跨年漂移：同性质数据今年 D、明年不得 B）。

## 一、统计期间与天数折算（最高频坑点 + 纵向可比基）

- **天数漂移是头号可比性杀手**：春节 2023=7天 / 2024=8天 / 2025=8天 / 2026=9天；十一 2023=8天(合并) / 2024=7天(拆分) / 2025=8天(合并) / 2026=7天(拆分)。
- **必填**：每条数据在「假期天数」「统计起止日」「口径版本」「统计窗口」四列标注。春节/十一「假期天数」缺失即触发 R1 告警（被 `audit_caliber.py` 拦截）。
- **折算规则**：跨年/调休/合并拆分导致天数变动时，**报告主叙事禁止用未折算绝对增量做"创新高"主标题**。必须同时提供：
  - **per-day 等效值**：日均 = 总量 ÷ 天数；或
  - **等效天数对比**：等效 N 天 ≈ 总量 × (N ÷ 总天数)。
  - 例：春节 9 天 8034.83 亿 vs 2025 八天 6770 亿，标题不得写「双创新高 +1264.81 亿」，应写「日均约 892.76 亿 vs 846.25 亿（+5.5%）」或「折算 8 天口径约 7150 亿 vs 6770 亿（+5.6%）」。
- **纵向比较铁律**：任何「去年同期/本年上期」对比，若两端假期天数不同，**先归一为日均或可比天数**，再谈增减；未折算的绝对量比较一律判为口径错误。

## 二、基期规范（拦截累计口径误用）

| 基期取值 | 含义 | 处置 |
| --- | --- | --- |
| `同比` | 较上一年同节假日 | 多数稳健，主流基期 |
| `较2019` | 疫前恒定基期 | 合理，但须与「同比」分列，不可混读 |
| `累计年初至今` | 年度累计（以旧换新等） | **高危**：不得与单假期总量并列，差可达 22 倍；报告须显式标注「年度累计口径，非单假期」 |
| `较节假日X` | 较指定节假日 | 用于本年上期回顾，须注明 X 是哪个节假日 |

- **累计口径拦截**：`基期=累计年初至今` 的以旧换新/促消费数据，进入报告时**禁止做"单假期增量"叙事**，仅作政策规模背景。
- **窗口内累计豁免**：黄金周/春运等窗口内累计（如「4/29-5/6 共 8 天」）判 `累计(窗口内)`，不误报，但须与「5 天口径」分列。

## 三、数值类型规范（解析数值列语义）

`数值` 列禁止混合四种语义而不标注。每条数据「数值类型」必须取值：

| 数值类型 | 示例 | 处置 |
| --- | --- | --- |
| `水平值` | 3.08 亿人次 | 可直接入趋势线 |
| `增长率` | +5.9% / 500% | 必须带统计基数；`数值` 含「%」「倍」一律判增长率 |
| `指数` | 百度指数 1000 | 须注明指数基准与平台 |
| `定性` | 第一/显著增长/趋势 | 不得进数值列趋势；`数值` 含「第一/趋势/显著」判定性 |
| `复合` | 64.1/414.1/265.4（Occ/ADR/RevPAR） | 须拆分多列或单列标注拆解，禁止裸「/」 |

- 复合值（37 处 R6 告警）须拆分为独立行或显式标注拆解顺序；`audit_caliber.py` 会扫描「/」与关键词提示拆分。
- **历史别名归一（实证）**：专家团 P0 历史 CSV 将 `复合` 写作 `复合值`（37 行），接入时**统一为 `复合`**；`水平值` 仅限纯数字，`数值` 为非数值（列表/定性句/「是」「超X成」「X月」）时必须标 `定性` 或 `复合`（实证 59 行误标 `水平值`，见 `references/historical-data-source.md` 第三节 R14）。

## 四、统一主题字典（9 类，强制取值）

> CSV「主题」字段**必须从本字典取值**，禁止自由命名。跨年按主题聚合时，同类信号才可被正确归并（修复 R5 漂移：政策宏观/政策与宏观、新消费/热门新消费并存问题）。

1. **总体**（官方核心指标：出游人次/总花费/跨区域量）
2. **交通出行**（铁路/民航/公路/水路/城市交通/迁徙）
3. **景区目的地**（景区接待/限流/文博/演艺/热门城市/县域/出境入境）
4. **酒店住宿**（RevPAR/ADR/OCC/渠道/档次）
5. **平台渠道**（携程/同程/飞猪/美团/途牛/抖音生活等 OTA 与内容平台）
6. **旅行社**（跟团/小团/定制/订单）
7. **消费宏观**（商务部/税务/央行/电影局/支付清算/社零/以旧换新）
8. **游客画像**（客群结构/出行方式/时长/人均）
9. **新消费**（演出/夜游/非遗/智能硬件/县域奔县等子类，探索性主题圈定项归入此类）

> 原「群众文化」「支付」「跨境」「放假安排」等自由标签，按上表归并（如「支付」→消费宏观、「跨境」→景区目的地-出入境、「放假安排」→总体/消费宏观）。

> **历史基线归一（实证映射）**：专家团 P0 历史 CSV（2023–2026，716 行）的主题取值存在别名漂移，接入时按此映射并入 9 类（实证频次见 `references/historical-data-source.md` 2.3 节）：`政策与宏观`(12)→消费宏观、`热门新消费`(42)→新消费、`目的地`(44)→景区目的地、`跨境`(6)/`出入境`(3)→景区目的地、`消费`(4)/`支付`(1)→消费宏观、`放假安排`(4)→消费宏观、`群众文化`(1)/`电影`(1)→消费宏观。`交通`/`酒店`/`平台`/`景区`/`总体`/`游客画像`/`旅行社` 短名与 9 类一致，保留。

## 五、口径类型取值表（采集口径 / 来源层级 L1-L4）

> 区分「指标是什么」（指标口径类型，第七节）与「怎么采的/谁发布的」（口径类型，本表）。两者都必填。

| 口径类型 | 层级 | 说明 |

| 官方总量 | L1 | 文旅部/商务部/交通运输部发布的全域总量 |

## 六、预测台账与缺口标记规范（闭环纵向）

> 这是「延续性」的机制底座：本期预测 → 下期回填核验 → 反哺预测方法论。

- **预测入账**：凡报告做出前瞻预测（下一节假日前瞻/中长期趋势点位），须在数据集以独立行记录：
  - `数据性质=预计`、`缺口标记=预判待回填`、备注写 `预测ID=[年度][节假日]-F01` 与「中心值/区间/置信度」。
  - 预测不得混入实测栏；报告正文预测须用「预测卡」组件并标明置信度（中/高/低）。
- **回填核验**：下一报告期阶段二「纵向数据归集」时，读取上一期 `缺口标记=预判待回填` 的行，填入实测值（新行 `数据性质=实际`），并在报告「上一周期预测复盘」节对比：
  - 预测值 → 实测值 → 偏差% → 归因（口径效应/外生变量/方法偏差）→ 收敛或失准判语。
  - 回填后原预测行 `缺口标记` 改为 `已回填-偏差X%`（或 `已回填-吻合`）。
- **缺口标记取值**：`空` / `全国总量缺项`（如暑假中国旅游研究院值缺失）/ `预判待回填` / `测算待核`。
- **诚实降级**：假期未发生（如 2026 十一）或数据未发布，预测标「置信度：中」并声明「待官方回填」，绝对不把预测当实测写入消费数字栏。

## 七、统一指标口径字典（防跨家族相加）

> CSV「指标口径类型」必须从本表取值。跨家族指标**分列不可相加**。

| 指标口径类型 | 说明 | 不可与…相加 |
| --- | --- | --- |
| 旅游总花费 | 文旅部全域游客出游总花费 | 商务部社零、平台GMV |
| 铁路客运量 | 国铁公共客运 | 公路人员流动量 |
| 公路人员流动量 | 含自驾跨区域（2024+） | 铁/民/水公共客运量 |
| 民航客运量 | 民航公共客运 | 公路人员流动量 |
| 水路客运量 | 水路公共客运 | — |
| 酒店间夜 | 已售客房×过夜天数 | 客流人次 |
| 酒店RevPAR | ADR×OCC | — |
| 商务部社零 | 重点企业/月度样本 | 旅游总花费 |
| 平台GMV | 平台自身成交额 | 旅游总花费/社零 |
| 客流人次 | 景区/商圈客流 | 旅游总花费 |
| 搜索量 | 百度/微信指数 | 任何消费金额 |
| 播放量 | 内容平台播放 | 任何消费金额 |
| 支付清算额 | 银联/网联线下消费 | 文旅部大盘（作交叉验证） |
| 离岛免税 | 海口海关/中免财报 | 旅游总花费（并列） |

- **交通口径冲突库**：公路「跨区域人员流动量」≠铁/民/水「公共客运量」，报告交通章须脚注提示；2023 营业性口径不得入跨年增速链（R2）。
- **GMV/客流/播放量单列**：不得混为同一「消费」概念；平台增速须披露统计基数并标「该平台自身口径，非全市场」。

## 八、人均 / 酒店 / 景区 / 中秋（沿用 v1.0 细则）

### 8.1 人均消费口径（per-trip vs per-day）
- per-trip：唯一合法称「人均消费」，单位「元/人次」。
- per-day：必须改名「人均每日消费」，单位「元/人天」，永久标 `数据性质=推算` 且等级 D。
- 禁止同报告混称「人均」；同框出现须区分单位与口径。

### 8.2 酒店口径
- 定义分列：间夜 / 预订量 / 履约间夜 / OCC / ADR / RevPAR（**三件套必填**，缺失标「本期无权威来源」）。
- 平台 C 级增速标「该平台自身口径，非全市场」；渠道结构（OTA/直营/会员+佣金率）、各档次（奢华/高端/中端/经济）为固定采集项。

### 8.3 景区口径
- 二消结构必采（门票/餐饮/住宿/文创/游乐拆解）；承载率/限流方式字典化；文博/演艺独立细分；客流增速 vs 二消增速背离须单列悖论分析。

### 8.4 中秋缺位规则（消除 6→5 缺口）
- 独立 3 天：按 holiday-config 中秋模板采集，命名 `[年度]中秋假期`。
- 合并超长：并入相邻国庆，命名 `[年度]十一假期（含中秋）`，备注标 `含中秋口径`。
- 禁止静默缺位：无独立中秋数据须在 overview.md 与真实性说明声明「本年中秋与国庆合并统计」。
