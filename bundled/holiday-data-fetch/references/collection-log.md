# 采集日志与增量归集规则（Collection Log & Merge Rules）v1.2

> 本文件定义采集过程中的日志记录规范，以及多轮采集后归集合并（append/merge）的去重与冲突规则。`merge_rounds.py` 与 `import_history.py` 按本规则执行。

---

## 一、采集日志（Collection Log）

每次采集会话生成 `采集日志.csv`，与 JSON 同目录落盘，字段：

`检索关键词 | 检索时间 | 标题 | 来源机构 | 报告/资料名 | 发布时间 | URL | 内容摘要 | 快照路径 | 层(layer) | 状态 | 观测批次 | 同源复用`

- 每条记录对应"检索词 × 来源"组合；同一来源多条数据可合并一行（摘要中列出）。
- URL 必须为可点击完整链接，禁止缩写。
- 旧闻（非目标年度/节假日口径）单独标记 `[旧闻-剔除]` 并注明真实年份，不入 JSON。
- `状态` 取值：`入库L1` / `入库L2` / `快照未存-原因` / `旧闻-剔除` / `冲突暂存` / `历史导入`。
- `观测批次`：本轮 `R1/R2…`，历史导入 `H1/H2…`（`gen_collection_log.py` 自动填充）。
- `同源复用`：快照文件被 ≥2 条引用时标 `是-共{n}条`，否则 `否`（R5 修复，便于追溯快照复用）。

## 二、同源双录（L1/L2 双轨记录）

每轮检索除结构化数据点外，**把榜单（TOP10 清单）、区间值、定性句（"显著增长""翻倍"）、政策事件（免签/消费券/放假安排）、平台热点等"现象级素材"一并记录**：

- 可直接入趋势线的统计值 → 记 L1（layer="L1"，22 字段）
- 榜单/区间/定性/政策/热点 → 记 L2（layer="L2"，现象素材字段）
- **同一来源的 L1 与 L2 可同时入库**，互不排斥（如官方总量入 L1，其附带的榜单入 L2）
- 双轨原则：L2 不因"入不了 22 字段口径"而被丢弃；宁多勿缺，唯一删除条件是**无 URL 佐证的纯臆测**

## 三、增量归集（多轮合并 + 历史导入）

### 3.1 工作区模型
- 主文件：`holiday-data-fetch.json`（单文件，唯一真源）
- 新轮次采集结果先写临时文件 `round_{R}.json`，经 `merge_rounds.py` 校验后合并进主文件
- 历史数据经 `import_history.py` 导入为 `观测批次=H{n}` 的存量基线

### 3.2 数据同一性分层判定（v1.2 核心）

合并/导入时，按下列层级依次判定（判定顺序不可颠倒）：

| 层级 | 判定条件 | 处理 |
| --- | --- | --- |
| **L1 同源同载体重采** | 来源URL + 报告/资料名 + 数据点 + 口径版本 + 统计窗口 + 数据性质 全一致 | 去重（保留 `采集时间` 最新一条）；同键不同值 → 冲突暂存（双保留+备注标"双口径/冲突"） |
| **L2 同源异性质并存** | URL+报告+数据点+口径版本+统计窗口 一致，但 `数据性质` 不同（预计 vs 实际） | 并存 + 自动回填 `观测关联`（见 3.5） |
| **L3 异源并存** | 数据点+口径一致，URL 或来源机构不同 | 全部保留（按来源区分） |
| **L4 异口径并存** | 数据点一致但口径版本/统计窗口不同 | 全部保留（口径不同即不同数据） |
| **L5 跨批次历史导入** | 历史导入 vs 本轮采集，键一致但采集时间不同 | 本轮优先更新；历史值入备注 `历史值:xxx(H1批次)`；若历史预测本轮实测 → 按 L2 并存 |

**禁止**在 L1 判定后直接丢弃异性质数据（预测/实测必须并存）。

### 3.3 合并流程（merge_rounds.py）
1. 读取主文件与新增轮次文件。
2. 逐条按 3.2 分层判定：
   - L1 去重 → 同值跳过，异值冲突暂存；
   - L2 并存 → 追加并回填观测关联；
   - L3/L4/L5 → 追加为新观测（L5 含历史值入备注）。
3. **冲突暂存**：同键不同值，不自行取舍，两条都保留并在 `备注` 标 `双口径/冲突`，归入 `meta.merge_notes`。
4. **id 追加**：新条目分配新流水 id（见 json-schema 第五节），已存在 id 不再改写。
5. **更新 meta**：`updated_at`、`rounds` 追加、`counts` 重算、`merge_notes` 记录本次变更摘要。
6. 输出原子写回（先写临时文件再替换，避免中断损坏）。

### 3.4 历史导入流程（import_history.py）
1. 读取历史数据（历史版 CSV / v1.0 JSON / v1.1 JSON，支持多路径）。
2. **质量过滤**：剔除待核/数值污染/无 URL。
3. **格式归一化 + 字段补齐**（缺地域粒度→推断或补"全国"并备注；缺推算依据→补备注；缺 snapshot→`未存-历史导入`）。
4. **批次标注**：`数据来源=历史导入`、`观测批次=H{n}`、`round=历史导入`、`采集时间=导入时刻`。
5. **分层判定**（按 3.2）合并进主 JSON。
6. 输出导入报告（读取/过滤/去重/新增条数），更新 `meta.history_imports`。

### 3.5 预测-实测对照自动回填
- 检测到 L2 并存（同键一条 `预计`、一条 `实际`）时：
  - 预测行：`观测关联=对照:实测{id}`；若其 `缺口标记=预判待回填` 则清除。
  - 实测行：`观测关联=对照:预测{id}`。
- 回填在合并（`merge_rounds.py`）与导入（`import_history.py`）阶段自动执行，无需人工。

### 3.6 覆盖规则
- 同键同值：保留首见，不重复。
- 同键不同值且跨批次（历史 vs 本轮）：本轮优先，历史值入备注 `历史值:xxx(H批次)`（L5）。
- 同键不同值且同为本轮：冲突暂存，双保留 + 备注标注（绝不静默覆盖）。
- 预测/实测：永远并存（L2），绝不因"新值"覆盖"旧性质"。

## 四、来源优先级与分级

| 等级 | 定义 |
| --- | --- |
| A | 政府公告/官方统计/权威通讯社通稿（文旅部、国铁集团、商务部、新华社、央视） |
| B | 权威媒体转引机构数据（新浪财经、光明网、澎湃转引 STR/航班管家） |
| C | 企业自我披露/券商研报/行业机构报告；C 级平台数据须标"该平台自身口径，非全市场" |
| D | 弱溯源/无法直接核实/推算；**推算/测算/弱溯源/定性类强制 D 级，禁入 B 级** |

**预计行等级（v1.2 澄清）**：官方权威机构发布的「预计」值（国铁集团、民航局、移民局、交通运输部、中国旅游研究院等官方预测）可信度高于 D 级推算，可按 A/B/C 标注；媒体/平台自行预计按弱溯源处理（降 D 或入 L2）。**推算/测算/弱溯源/定性仍强制 D**。

**交叉印证要求**（探索性主题/新消费）：
- 入选须满足 ≥2 个**不同机构** URL，且在 JSON 中同一主题项目互链（同一条目出现 ≥2 条不同机构记录）。
- 仅 1 源或同源多 URL → 降级"待核实"，仅入 L2 备注，不进报告主叙事。

## 五、采集深度与覆盖自检

- **行数门禁**：春节/十一 ≥35、五一/端午/独立中秋 ≥25、暑期 ≥30（见 `holiday-keywords.md` 第五节）；丰富线：春节/十一 ≥60、五一/端午/独立中秋 ≥45、暑期 ≥55。
- **全源覆盖**：A+B+C 必采，E/F 至少一组；B≥2 机构、C≥3 平台、地方政务≥3 省市。
- **本轮新增占比**（v1.2 新增）：本轮采集条目占全部条目比例 <40% WARN（防只导历史、不采新数据）。
- 未达标须在 `meta.merge_notes` 与交付说明显式声明缺口，禁止静默缺位。

---

## 六、数据性质纪律

- `实际`：实测数据
- `预计`：事前预测（`缺口标记=预判待回填`，备注含 `预测ID=[年度][节假日]-F0X`；实测发布后回填 `观测关联`）
- `推算`：派生值（per-day 人均、等效天数折算等），强制 D 级，与实测分栏

**预测纪律**：假期未发生/数据未发布时，不得把预测当实测写入；预测行独立标记，报告端用预测卡呈现并标置信度。预测与实测并存（观测序列），供预期差分析。
