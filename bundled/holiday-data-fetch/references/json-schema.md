# 统一 JSON 数据字典（Unified JSON Schema）v1.2

> `holiday-data-fetch` 的**唯一产物**是单文件 JSON（默认 `holiday-data-fetch.json`）。原 `holiday-data-report` 的 L1（22 字段结构化层）与 L2（现象素材层）在这里**统一合并为一个文件**，仅用 `layer` 字段区分。
> 本文件定义完整数据字典，供脚本校验与报告端消费。
> **v1.2 核心扩展**：① 观测序列化管理（`采集时间`/`观测批次`/`观测关联` 三字段）；② 历史数据导入规范（`数据来源=历史导入`）；③ 数据同一性分层判定（L1–L5）；④ 枚举统一（主题 `支付交易`、地域粒度 `景区商圈级`）。

---

## 一、文件级结构

```json
{
  "schema": "holiday-data-fetch-v1",
  "meta": { ... },
  "items": [ { "layer": "L1", ... }, { "layer": "L2", ... } ]
}
```

- `schema`：固定 `"holiday-data-fetch-v1"`，脚本据此识别版本。
- `meta`：采集归集元信息（见第二节）。
- `items`：统一条目数组，**每条必须含 `layer` 字段**，取值 `"L1"` 或 `"L2"`（label 区分层）。

---

## 二、meta 字段

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| `year` | 目标年度 | `2026` |
| `holiday` | 目标节假日 | `"十一"` |
| `region` | 地域 | `"全国"` |
| `created_at` | 首次创建日期 | `"2026-08-27"` |
| `updated_at` | 最近归集日期 | `"2026-08-28"` |
| `rounds` | 采集轮次列表 | `["2026-08-27-R1", "2026-08-28-R2"]` |
| `caliber_version` | 口径字典版本引用 | `"holiday-data-report-caliber-v2.1"` |
| `holiday_config_version` | 检索词矩阵版本 | `"holiday-keywords-v1.2"` |
| `merge_notes` | 归集备注（合并/口径差异/中秋合并等） | `["R2 新增 12 条 L1", "H1 导入 45 条历史 L1, 过滤 12 条"]` |
| `counts` | 统计 | `{"L1": 38, "L2": 26, "snapshots": 30, "history_imported": 45}` |
| `history_imports` | （可选）历史导入记录数组 | `[{"batch":"H1","source":"data_set/2024春节/合并.csv","read":115,"filtered":12,"deduped":6,"imported":45,"at":"2026-08-28"}]` |

> `counts.history_imported`：历史导入条数累计（供门禁"本轮新增占比"统计）；`meta.history_imports` 记录每次导入批次明细。

## 三、L1 条目字段（layer="L1"）

> L1 为**结构化统计层**，字段与原技能 22 字段**完全对齐**（向后兼容 `holiday-data-report` 阶段二口径治理），另加采集附加字段（见 3.2）。

### 3.1 原 22 字段（必填，取值规则沿用口径字典）

| # | 字段 | 说明 / 示例 |
| --- | --- | --- |
| 1 | 主题 | 统一主题字典：总体/交通出行/景区目的地/酒店住宿/平台渠道/旅行社/消费宏观/游客画像/新消费/**支付交易**（支付数据统一 `支付交易`；废弃 `支付` 写法，见三·B 枚举白名单） |
| 2 | 数据点 | canon 短名（去年份/去节假日名，如 `国内旅游出游人次`） |
| 3 | 数值 | 数字或定性 |
| 4 | 单位 | 亿人次/亿元/%/元… |
| 5 | 单位粒度 | 人次/人天/人均trip/人均day/亿元/百分比/元/间夜 |
| 6 | 统计起止日 | `2026-10-01 至 2026-10-07` |
| 7 | 统计窗口 | `7天`/`5天`/`7-8月合计`/`7月单月` |
| 8 | 口径版本 | `7天口径`/`8天口径`/`合并口径` |
| 9 | 指标口径类型 | 旅游总花费/铁路客运量/公路人员流动量/酒店RevPAR/平台GMV/社零…（防跨家族相加） |
| 10 | 口径类型 | 官方总量/官方跨区域(含自驾)/官方营业性(不含自驾)/官方重点监测/平台自披露/行业协会计/测算/弱溯源/待核 |
| 11 | 数据性质 | 实际/预计/推算 |
| 12 | 基期 | 同比/较2019/累计年初至今/较节假日X |
| 13 | 假期天数 | 7/8/9/5/3/62 |
| 14 | 数值类型 | 水平值/增长率/指数/定性/复合 |
| 15 | 采集日期 | `2026-08-27`（沿用 22 字段兼容位；完整时点见 `采集时间`） |
| 16 | 缺口标记 | 空/全国总量缺项/预判待回填/测算待核 |
| 17 | 来源机构 | 机构名 |
| 18 | 报告/资料名 | 报告名 |
| 19 | 发布时间 | 年份或日期 |
| 20 | 可信度等级 | A/B/C/D |
| 21 | URL | 可点击链接（无公开URL须如实标注+替代路径） |
| 22 | 备注 | 自由文本（双口径/弱溯源/平台自身口径/含中秋口径/预测ID/历史值/历史重复 等） |

**强制 D 规则（v1.2 口径澄清）**：
- **强制 D**：`数据性质=推算`、`口径类型∈{测算,弱溯源}`、`数值类型=定性`（非定量弱描述）的数据点，`可信度等级` 强制 `D`、禁入 B，且不得与实测混同。
- **权威官方预计可 A/B/C**：`数据性质=预计` 且为**官方权威机构发布的预测值**（如国铁集团、民航局、移民局、交通运输部、文化和旅游部、中国旅游研究院等发布的官方预测），可信度高于 D 级推算，可按 A/B/C 标注；媒体/平台自行预计仍按弱溯源处理（降 D 或入 L2）。
- 机构实测发布的复合/增长率指标（如 STR RevPAR=ADR×OCC）按其实测等级（A/B/C）标注，不受此限。

### 3.2 采集附加字段（L1 与 L2 通用）

| 字段 | 层级 | 说明 | 示例 |
| --- | --- | --- | --- |
| `layer` | 通用 | 层级 label | `"L1"` |
| `id` | 通用 | 全局唯一 ID | `2026-11-L1-001`（年-节序号-层-流水） |
| `内容摘录` | 通用 | 原文正文要点（支撑"保存网页"语义价值） | `"出游8.03亿人次，同比+5.9%…"` |
| `snapshot` | 通用 | 网页快照相对路径 | `"snapshots/文旅部_国庆假期文旅数据.html"`；历史导入行标 `"未存-历史导入"` |
| `round` | 通用 | 采集轮次（本轮）或 `"历史导入"` | `"2026-08-27-R1"` |
| `keywords` | 通用 | 命中检索词（追溯） | `"2026 国庆 文旅部"` |
| `地域粒度` | **仅 L1，必填** | 数据地域粒度枚举：`全国`/`省级`/`城市级`/`景区商圈级`/`跨区域`（可附括号标注如 `省级(广东)`、`城市级(北京)`） | `"全国"`、`"省级(广东)"` |
| `推算依据` | L1/L2，可选 | 派生指标的计算公式/基期/来源说明（推算行必填） | `"总花费÷出游人次=人均消费; 基期=文旅部总量"` |
| `采集时间` | 通用 | **观测管理主键**：本条数据被本技能采集/导入入库的完整时点，格式 `YYYY-MM-DD HH:MM` | `"2026-08-28 14:30"` |
| `观测批次` | 通用 | **观测批次码**：本轮 `R1/R2…`；历史导入 `H1/H2…`（追溯来源轮次） | `"R2"`、`"H1"` |
| `数据来源` | 通用 | 本条数据入库来源：本轮采集省略或 `"本轮采集"`；历史导入必填 `"历史导入"` | `"历史导入"` |
| `观测关联` | 通用，可选 | 预测-实测对照关联（见四·D）：预测行/实测行互为对照 | `"对照:实测{id}"`、`"对照:预测{id}"` |
| `快照复用` | 通用，可选 | 同源复用标记：快照文件被多条引用时标注 `"复用-共{n}条"`（非首见条） | `"复用-共3条"` |

> **地域粒度采集要求（v1.1/v1.2）**：每组合中，全国级数据占比 ≤60%；省级+城市级+景区商圈级合计 ≥30%（评估发现 v1.0 全国级占比 64%，细粒度数据严重不足）。历史导入行缺地域粒度时按数据点/来源推断，无法推断补默认 `全国` 并在备注标注。

## 三·B 观测序列化管理（v1.2 新增）

> **核心理念**：数据即"观测序列"，而非"唯一事实"。同一指标在不同时点（节前预测 → 节中快评 → 节后实测）、不同机构（官方/行业协会/平台/券商）产生多个观测值，每个观测都有独立分析价值（机构预测 vs 官方实测 → 预期差分析）。

| 时间戳字段 | 含义 | 用途 |
| --- | --- | --- |
| `采集时间` | 本条数据被本技能采集/导入入库的时间（`YYYY-MM-DD HH:MM`） | **主管理键**，区分观测批次 |
| `发布时间` | 数据源官方发布时间（22 字段之一，沿用） | 判断预测/实测时间线 |
| `观测批次` | `R1`/`R2`（本轮）/ `H1`/`H2`（历史导入） | 追溯来源轮次与批次 |

**管理原则**：
- 除非来源载体完全一致（同源同载体重复采集），否则**所有观测并存**，按采集时间序列化管理。
- 预测（`数据性质=预计`）与实测（`数据性质=实际`）**并存不覆盖**，互为对照（见四·D）。
- 历史导入为"存量保底"（防"越采越少"），本轮采集为"增量"（新增观测 + 同源更新），叠加整合而非简单合并。

### 数据同一性分层判定（去重/并存规则）

| 判定层级 | 判定条件 | 处理 |
| --- | --- | --- |
| **L1 同源同载体重采** | 来源URL + 内容载体(报告/资料名) + 数据点 + 口径版本 + 统计窗口 + 数据性质 全部一致 | 视为同一观测重复采集 → **去重**，保留采集时间最新一条；同键不同值 → 冲突暂存（双保留+备注标"双口径/冲突"） |
| **L2 同源异性质并存** | URL+载体+数据点+口径一致，但 `数据性质` 不同（预计 vs 实际） | 视为**预测/实测两个观测** → 并存，建立对照关联（见四·D） |
| **L3 异源并存** | 数据点+口径一致，但 URL 或来源机构不同 | 视为不同观测 → **全部保留**，按来源区分 |
| **L4 异口径并存** | 数据点一致但口径版本/统计窗口不同（如 7天 vs 8天、含自驾 vs 不含自驾） | 全部保留（口径不同即不同数据） |
| **L5 跨批次历史导入** | 历史导入 vs 本轮采集，键一致但采集时间不同 | 本轮优先更新；历史值入备注 `"历史值:xxx(H1批次)"`；若历史为预测而本轮为实测 → 按 L2 并存 |

> 判定顺序：先按完整键查重（L1），再检查数据性质差异（L2），其余落 L3/L4/L5。**禁止在 L1 判定后直接丢弃异性质数据。**

### 枚举白名单（R2 修复 · 消除双写）

| 字段 | 合法取值 | 废弃写法（门禁 WARN） |
| --- | --- | --- |
| `主题` | 总体/交通出行/景区目的地/酒店住宿/平台渠道/旅行社/消费宏观/游客画像/新消费/支付交易/出入境/派生指标/分省分市（覆盖 v1.1 实际产出 13 种） | `支付`（应统一 `支付交易`）、`酒店`（→酒店住宿）、`平台`（→平台渠道）、`交通`（→交通出行） |
| `地域粒度`（基础值） | 全国/省级/城市级/景区商圈级/跨区域 | `景区级`（应统一 `景区商圈级`） |

> `validate_fetch.py` 对废弃写法输出 WARN 并提示统一，不阻塞 PASS；`地域粒度` 附注括号形式（如 `省级(广东)`）合法，校验基础值即可。

## 四、L2 条目字段（layer="L2"）

> L2 为**现象素材层**：榜单/区间/定性/政策事件等，不做 22 字段口径强制，轻量标签化，保留时点丰度。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `layer` | 是 | `"L2"` |
| `id` | 是 | `2026-11-L2-001` |
| 现象标签 | 是 | 自由标签数组（避暑游/反向旅游/研学/政策事件/平台榜单…），跨期归并用 |
| 主题归属 | 是 | 按 9 类主题字典归类（仅归类，不强校验） |
| 现象描述 | 是 | 素材核心描述 |
| 数值 | 否 | 原样保留，不做折算 |
| 单位 | 否 | — |
| 数值类型 | 是 | 定性(区间/约)/水平值/增长率… |
| 素材类型 | 是 | 数据点/榜单清单/定性陈述/区间值/政策事件/图文摘录/图表 |
| 来源机构 | 是 | 机构名 |
| 来源URL | 是 | 可点击链接 |
| 采集日期 | 是 | `2026-08-27` |
| 与L1指标键 | 否 | 有对应 L1 指标时填 canon 数据点，否则空 |
| 内容摘录 | 是 | 原文要点 |
| `snapshot` | 是 | 快照相对路径或 `未存-原因`（历史导入行 `未存-历史导入`） |
| `round` | 是 | 采集轮次或 `"历史导入"` |
| `keywords` | 是 | 命中检索词 |
| `采集时间`/`观测批次`/`数据来源`/`快照复用` | 是 | 同 L1 通用字段规范（见 3.2） |

> L2 唯一删除条件：无 URL 佐证的纯臆测。其余素材**宁多勿缺**全部保留。

## 四·B 推算行 A/B 分类策略（v1.1，v1.2 沿用）

> **背景**：v1.0 对推算/预计行过度保守（倾向剔除），导致客单价/人均等核心分析指标从 38 条骤降至 5 条。v1.1 起按价值分类处理，**保留有分析价值的派生数据**，同时守住"推算禁入 B 级、与实测分栏"红线。

### A 类（保留入库 · 强制 D 级）
有明确分析价值的派生指标，保留并标注推算依据：
- 客单价 / 人均消费（per-trip）
- 人均每日消费（per-day）
- 日均等效值 / 等效天数折算
- 跨年可比、恢复度（vs 2019）
- 行业景气指数、券商测算

**要求**：`数据性质=推算/预计`、`可信度等级=D`、`备注` 注明推算公式或来源、`推算依据` 字段填公式/基期（如 `总花费÷出游人次`）。官方机构发布的「预计」按 3.1 强制 D 规则可标 A/B/C。

### B 类（剔除 / 降级 L2）
无价值或不可靠的推算：
- 无明确口径的模糊推算（"约""估计"无公式无基期）
- 媒体未经核实的"预计"数字
- 与实测重复的简单换算

**处理**：不入 L1；有价值者降级入 L2 现象素材（`素材类型=定性陈述`），无价值者直接剔除。

### 门禁约束
- 推算/预计行占比 **≤30%**（防止泛滥），不设下限（允许为 0）。
- 推算行永远与实测分栏，报告端不得混入消费数字栏。

## 四·C 历史数据导入规范（v1.2 新增）

> 历史数据（历史版 CSV / v1.0 JSON / v1.1 JSON）通过 `scripts/import_history.py` 导入，作为**存量基线**叠加进主 JSON，防"越采越少"。

| 处理项 | 规则 |
| --- | --- |
| **质量过滤** | 剔除：`口径类型=待核`、数值类型污染（如单位粒度/数值误填假期天数）、无 URL 且无替代路径、与目标年度/节假日不符 |
| **格式归一化** | 自动识别历史版 CSV（22 字段）/ v1.0 JSON / v1.1 JSON 并映射为统一条目 |
| **字段补齐** | 缺 `地域粒度` → 按数据点/来源推断，无法推断补 `全国` 并备注；缺 `推算依据` → 补备注；缺 `snapshot` → `未存-历史导入` |
| **批次标注** | `数据来源=历史导入`、`观测批次=H{n}`、`round=历史导入`、`采集时间=导入时刻` |
| **分层判定** | 与工作区已有条目按 L1–L5 分层判定（L1 去重 / L2 预测实测并存 / L5 跨批次，见三·B） |
| **快照** | 历史行一律不补抓快照，`快照=未存-历史导入`，不计入本轮快照覆盖率 |

## 四·D 预测-实测对照关联（v1.2 新增）

- 预测与实测并存后建立显式关联，供报告端做预期差分析。
- 新增字段 `观测关联`：
  - 预测行：`观测关联=对照:实测{id}`（实测发布后由合并/导入阶段自动回填；此前标 `缺口标记=预判待回填`）
  - 实测行：`观测关联=对照:预测{id}`
- 回填时机：合并（`merge_rounds.py`）/导入（`import_history.py`）阶段检测到"同键预测+实测并存"时自动回填，并清除预测行 `缺口标记=预判待回填`。
- 判定同键：URL+报告/资料名+数据点+口径版本+统计窗口一致，且一条 `数据性质=预计`、另一条 `数据性质=实际`（L2 判定）。

## 五、id 规范

- 格式：`{年份}-{节假日序号}-{层}-{3位流水}`
- 节假日序号：春节=CH、端午=DW、五一=WY、暑期=SH、中秋=MQ、十一=SY
- 示例：`2026-SH-L1-014`、`2026-SY-L2-007`
- 由 `merge_rounds.py` / `import_history.py` 自动分配，追加不改号，保证跨轮/跨批次稳定。
