# 网页快照规则（Snapshot Rules）v1.0

> 本技能**极端强调数据采集能力**，其中一项硬性要求是：**保存所获取的网页文件**。凡 JSON 条目含 URL 者，均须尽力下载原文网页保存为本地快照，与条目 `snapshot` 字段互链。快照是"必做动作"，而非"尽力而为"的可选项。

---

## 一、快照目录

```
{输出目录}/snapshots/{来源机构}_{标题摘要}.html
```

- 与 `holiday-data-fetch.json`、`采集日志.csv` 同目录。
- 标题摘要：取标题前 12–16 个字符，去除 `\/:*?"<>|` 等非法字符。
- 示例：`snapshots/文旅部_国庆假期文旅数据.html`

---

## 二、采集动作（每轮必做）

对每条含 URL 的记录：

1. **拉取正文**：用 `web_fetch`（或等价网页获取工具）拉取该 URL 的页面正文。
2. **存快照**：将页面内容保存为 `snapshots/{机构}_{标题摘要}.html`（UTF-8 编码）。
3. **写摘录**：将正文要点提取为 `内容摘录` 字段（150 字以内，覆盖关键数字与口径），写入 JSON 条目——即使快照保存失败，摘录也保证语义价值不丢。
4. **关联**：条目 `snapshot` 字段填相对路径。

---

## 三、失败降级（不阻断采集）

| 失败情形 | 处理 |
| --- | --- |
| 页面不可达/超时 | `snapshot` 填 `未存-网络不可达`，`内容摘录` 依据检索摘要填写，备注记原因 |
| 页面为动态渲染/需登录 | `snapshot` 填 `未存-动态页/需登录`，必要时改用浏览器通道或放弃快照 |
| 原文为 PDF/图片 | 尽量下载原文件至 `snapshots/`（保留原扩展名），否则按不可达处理 |
| 下载内容为空 | 重试 1 次；仍空则 `未存-空页面` |

**铁律**：快照失败**不得**导致该条数据点被丢弃——数据仍入库（L1/L2），仅 `snapshot` 标记未存原因；`内容摘录` 是最后兜底。

---

## 四、快照与条目一致性

- 快照文件名、JSON 条目 `snapshot` 字段、采集日志 `快照路径` 三者一致。
- 交付前用 `validate_fetch.py --check-snapshots` 核对：JSON 中 `snapshot` 非 `未存*` 的文件必须真实存在于 `snapshots/`。
- 快照覆盖率 = 已存快照条目数 ÷ 含 URL 条目总数；目标 ≥ 80%，低于须在交付说明声明缺口。

### 4.1 同源复用标注（v1.2 新增，R5 修复）

- 同一快照文件被多条 JSON 引用（同源多指标共用一页）属正常优化，但须显式标注便于追溯。
- 规则：交付前统计快照引用次数；被 ≥2 条引用的快照，其**非首见条** `snapshot` 字段追加标注 `快照复用=复用-共{n}条`，采集日志 `同源复用` 列同步标 `是-共{n}条`。
- 由 `gen_collection_log.py` 自动统计标注（不要求人工填写）。

### 4.2 历史导入行快照（v1.2 新增）

- 历史导入行（`数据来源=历史导入`）**一律不补抓快照**，`snapshot=未存-历史导入`。
- 历史导入行**不计入本轮快照覆盖率**（单独统计），本轮条目快照覆盖率仍须 ≥80%。

---

## 五、版权与隐私红线

- 原文快照**仅本地留存**，不入公开报告；引用时给可点击 URL，不整篇转载。
- 快照仅作溯源证据与离线复核用，不用于对外发布。
